## Статус

Технический контракт этапа 11.1 плана «Stage 7 — Data Closure Assurance» в
постановке владельца от 2026-10-12. Кода нет. Пока контракт не реализован, он
не является гейтом: `authoring.py next` и Stage 9 работают как раньше.

**Что изменилось.** Первая редакция (до `2619356` включительно) описывала
`data_closure` как раунд «Почемучки»: рецензенты читают готовые notes,

постановку (§0): State 7 — это **среда, в которой notes пишутся**, а не гейт,
который ищет данные в уже написанных notes. Механика рецензентов сведена к
истории (§12). Что из первой редакции сохранилось:

- нормативная база §15 (§1);
- решение Q1 о двух слоях: авторские источники до сборки, механический гейт
  охвата на `state8_assembly` (§7);

- кандидаты Cabinet Kernel как регрессии (§10).

`tools/factory_slice_workbench/service.py`: он изменён PR #115, ссылки на него

## 0. Постановка узла (решения владельца, 2026-10-12)

1. **State 7 — среда написания notes.** Операторы пропускают §15, когда пишут
   notes, и данные оказываются в прозе. Искать их потом в готовом тексте —
   поздно и дорого. Поэтому на узле State 7 сидит агент с одной задачей:
   писать notes модуля сразу по §15, без данных в прозе.
2. **Рецензенты и судьи для размещения данных не нужны.** Агент пишет с
   инструментами, итог проверяет механический lint без модели. Схема
   вердиктов, судья и раунды первой редакции сняты (§12).
3. **Contradictions остаются последним шагом State 7** — после сборки, на
   боевых промптах Фабрики (PR #115), по модулю. Противоречие правки с
   контрактом, моделью или другой note видно только в промпте модуля, а
   промпт существует только после сборки.
4. **Решение Q1 сохраняется** (`2619356`): слой 1 работает по авторским
   источникам до сборки (привязка M6 — контракты State 6 и модели
   `60_model_closure*.json`), слой 2 — механический гейт охвата на
   `state8_assembly`. Слоем 1 теперь служат среда написания и lint, а не
   раунд рецензентов.

## 1. Нормативная база: пункты §15

| Пункт | Что берёт среда |
|---|---|
| §15, вводная (стр. 1756–1781) | Четыре механизма: `derivation`, `placement`, `lowering`, `legacy recovery`. Без ячейки обходится только `derivation`, и только если результат доказуем из объявлений и версии backend-а (стр. 1778–1781). Агент не пишет значение, «выводимое» без такого доказательства (решение Q6). |
| §15.1 (стр. 1785–1802) | В спеке только значения времени сборки. Иллюстративные значения и значения внешней системы в notes запрещены. Основание правила L2 и запрета примеров в инструкции агента. |
| §15.2 (стр. 1916–1939) | Ровно один дом; процедура тотальна: неразмещённое значение — дефект, а не повод для прозы. Основание остановки агента с запросом на структуру (§5): прозу вместо дома агент не пишет. |
| §15.3 (стр. 1943–1959) | Note обращается к данным только адресом; воспроизводить содержимое блока запрещено; ссылка резолвится в наименьший узел. Основание инструментов M1, M2 и правил L1, L2. |
| §15.3.1 (стр. 1961–1994) | Три законных пути значения к коду: `= models.*`, константа поставщика (`the imported X constant`), поле настроек. Какие `= rules.*` / `= config.*` законны; адрес без `=` невалиден. Грамматика адресов агента и правило L1. |
| §15.4 (стр. 1999–2023) | Лист в двух домах запрещён; обязанные совпадать значения имеют один дом. Агент не заводит второй дом и не копирует значение между notes. |
| §15.5.1 (стр. 2071–2130) | Выводимые storage-ограничения не повторяются; codec принадлежит backend-у. Агент не пересказывает их в notes. |
| §15.9 (стр. 2227–2259) | Модель-генератор не видит значений; literal-check ловит протечку через notes. Основание L2. |
| §15.10 (стр. 2263–2298) | `NOT_APPLICABLE` — только итог выполненной процедуры; неоднозначность не решается статистикой. Основание fail-closed правил lint и запрета «молча пропустить» модуль. |
| §15.11 (стр. 2302–2333) | NOT-list: таблицы, пороги, allow-list, alias-словари, пути, ставки, коэффициенты в notes — дефект; «последовательность операций как значение спеки» запрещена, значит, алгоритм остаётся прозой. Граница между тем, что агент пишет словами, и тем, что он адресует. |

## 3. Вход агента по модулю

Единица работы — **модуль привязки M6**: модуль, которому принадлежат
контракты State 6 или модели `60_model_closure*.json` (решение Q1). Агент
пишет notes всех таких модулей, не выясняя, какие из них генерирует модель:
множество LLM-модулей знает только Фабрика, и его сверяет слой 2 (§7).

| Вход | Откуда | Зачем агенту |
|---|---|---|

| Модели, которые видит модуль | `60_model_closure*.json`; поля и члены перечислений | Адреса `= models.*`; имена полей законно называются словами (`[FIELD_ASSIGNMENT]`, `[RETURN_SHAPE]`) |
| Адресуемые данные | `60_data_closure.json` (`config`, `rules`, `persistence`, `properties`, `determinism`; `placements` с `source_refs`, `design_stage6_data.py:28, 136–249`), `70_data_provider_closure.json` (константы поставщика), `70_*_closure.json` backend-ов | Дома значений; через M1, M2, M4, а не целиком в тексте |

## 4. Инструменты пишущего агента

Все инструменты только читают. Агент вызывает их **во время написания**, а
не получает готовый отчёт: ему нужно спросить «есть ли дом у `30 seconds`?»
в момент, когда он собирается это написать.

| # | Инструмент | Вопрос агента | Ответ | Основание |
|---|---|---|---|---|
| M1 | Резолвер адреса | «`= rules.x.y` существует? Это наименьший узел? Форма законна?» | узел, вид (лист / поддерево), канонический JSON, sha256; отказ с причиной | §15.3, §15.3.1 |
| M2 | Поиск по значению | «У значения `30`, `"21.00"`, `personal_data` есть дом?» | адреса, где лежит нормализованный литерал (строки, числа, строки фиксированной точности, члены перечислений) | §15.3, §15.9 |
| M4 | Поиск отсутствия | «Есть ли где-нибудь `timeout`, `retry`, `ceiling`?» | совпадения ключей и значений в `models` / `config` / `rules` / `contracts` и sha256 просмотренных пространств | §15.2 (тотальность) |
| M3 | Детектор сигналов данных | «Есть ли в моём тексте данные?» | числа, строки в кавычках, пути, перечисления ≥3 идентификаторов, члены перечислений, стрелки соответствий, табличная разметка | §15.11 |
| M6 | Привязка `scope → module` | (для среды) какие notes и символы принадлежат модулю | таблица по авторским источникам | решение Q1 |
| M5 | Lint | (для среды) проходит ли текст правила L1–L3 | §6 | §15.3, §15.9, §15.11 |

Правило агента: **есть дом → писать адрес; дома нет → остановиться** (§5).
M3 агент вызывает перед сдачей текста: тот же детектор потом применяет lint
(L3), и сигнал, который агент не закрыл, остановит модуль.

Чего у инструментов нет сегодня:

- **M1.** Своего резолвера у Workbench нет: notes gate принимает любого
  потомка известного адреса (`gate.py:296–299`), модели знает только по
  корню (`gate.py:103–112`). Решение — вопрос Q5 (§13), рекомендован
  собственный резолвер Workbench со сверкой с Фабрикой.
- **M2, M4.** Нет. Индекс значений и поиск отсутствия строятся заново по
  авторским источникам.
- **M3.** Нет; механические правила сигналов для перечислений и повторов
  уже сформулированы в `tools/DATA_CLOSURE_RESEARCH_Q9_Q10_Q11.md` §5.1
  (M-E1, M-E5, M-O1).
- **M6.** `note_parser.parse(project, module_symbols, module_name)` делает
  привязку для одного модуля; нужна полная таблица. На Cabinet Kernel привязка
  507 notes по авторским источникам совпала с привязкой по собранной спеке

Существующие инструменты, которые среда использует без изменений:
`notes_workbench.language.authored_notes`, `ADDRESS_RE` /
`BARE_DATA_ADDRESS_RE` / `POSITIONAL_ADDRESS_RE` (`gate.py:25–30`),
`design_stage6_data` (provenance размещений), `workbench_mcp.service`

провайдер агента не фиксирован (решение Q4, §13).

## 5. Остановка: запрос на структуру

Если у значения нет дома, агент **не пишет его в прозу и не изобретает дом**.
Он останавливает модуль и возвращает запрос.

### 5.1 Когда агент останавливается

- Значение нормативно (его изменение меняет поведение модуля), а M2 и M4 не
  находят дома.
- Закрытое соответствие `A × B → C`, список вариантов, порог, путь, ставка
  или коэффициент нужны note, а в `models` / `config` / `rules` их нет
  (§15.2 проверки 3–5, §15.11).
- Дом есть, но адрес незаконен по §15.3.1 (например, `= rules.x` на
  продуктовых данных), и законного пути нет.
- Дом найден в двух местах (§15.4) — выбирать между ними агент не вправе.

Агент **не** останавливается, если значение — шаг алгоритма над
адресованными данными, условие поведения, пояснение или runtime-поле модели
(§15.11, §15.1): это проза. Порядок сортировки по полям объявленных моделей —
проза (решение Q10, правило M-O1).

### 5.2 Форма запроса

```json
{
  "schema_version": "spec_workbench_structure_request.v1",
  "module": "<module>",
  "need": "<что note должна сказать, одной фразой>",
  "value_kind": "threshold|path|rate|coefficient|allow_list|mapping|enumeration|other",
  "candidate_values": ["<значение, как его видит агент, из какого источника>"],
  "sources": [{"path": "02_rules_runs.md", "line": 41, "quote": "..."}],
  "absence": {"terms": ["..."], "namespaces": {"rules": "<sha256>", "config": "<sha256>", "models": "<sha256>"}},
  "homes_considered": [{"home": "rules.<backend>.<leaf>", "why_not": "..."}],
  "route": "state6|author|owner",
  "blocked_notes": ["<scope>: <class>"]
}
```

- `absence` — вывод M4: термины и дайджесты просмотренных пространств.
  Запрос без него не принимается: «дома нет» должно быть доказано (§15.10).
- `route`:
  - `state6` — дом по §15.2 однозначен, его нужно завести в State 6
    (`60_data_closure.json`, модель, константа поставщика);
  - `author` — значение не следует из текстов States 0–5, его должен дать
    автор;
  - `owner` — дом неоднозначен (проверки 3/4 или 4/5 §15.2 не различаются
    по тексту) или нужно продуктовое решение.
- Запросы модуля лежат в `examples/<case>/notes_authoring/<module>/
  requests.json` (ветка проекта). Это вход следующего захода агента и
  свидетельство для оператора; гейт их не закрывает.
- Секвенсер показывает запрос `state6` блоком фазы
  `pre_contract_structured_data_closure`, запросы `author` / `owner` —
  блоками `state7_notes` (решение Q17).

### 5.3 После ответа

Запрос закрывается правкой источника (State 6, решение, модель) — не правкой
запроса. Агент снова пишет модуль: M2 теперь находит дом, и note получает
адрес. Запрос, чьи `absence.namespaces` больше не совпадают с текущими
дайджестами, устарел: его надо перепроверить, а не держать открытым.

## 6. Механический lint (без модели)

Правила добавляются к детерминированному гейту фазы `state7_notes`
(`tools/design_notes.py --gate`, `notes_workbench.gate.coverage`,
`gate.py:311`) и выполняются на всех `80_notes*.md` (вопрос Q12).

| Код | Правило | Инструмент | Нарушение |
|---|---|---|---|
| L1 | Каждый `= <адрес>`, `the imported X constant` и поле настроек резолвятся в существующий наименьший узел; форма законна по §15.3.1; адрес данных без `=` запрещён | M1 | BLOCK |
| L2 | В тексте note нет литерала, равного объявленному значению (M2). Не считаются значениями: имена полей, моделей и контрактов; член перечисления рядом со своим `= models.X` как условие (M-E1, M-E5) | M2 | BLOCK |
| L3 | Каждый сигнал данных (M3) покрыт: он входит в адрес, это имя поля / модели / контракта, член перечисления при своём адресе, или ключ сортировки из полей объявленной модели (M-O1) | M3 | BLOCK |
| L4 | Note перечисляет все члены `X` рядом с `= models.X` (M-E2) или в порядке, отличном от объявленного (M-E3) | M3 + `models` | BLOCK (повтор или противоречие модели) |
| L5 | Общий отрезок прозы ≥10 слов в notes разных модулей (M-D1); списки в копиях различаются (M-D2) | все фрагменты | отчёт, не BLOCK — до решения Q11 |

- Lint не выносит вердиктов «данные / не данные»: он проверяет, что агент
  выполнил правило. Сигнал, который нельзя покрыть адресом, — повод для
  запроса на структуру (§5), а не для пояснения в note.
- Ложное срабатывание L2/L3 исправляется только сужением детектора (новое
  правило вида M-E5 в `tools/`), не правкой note и не исключением модуля
  (решение Q16).
- Модуль без notes проходит lint, только если M6 нашла модуль и проверка
  выполнена (§15.10): в отчёте есть модуль и пустой список notes.

Условия, при которых lint не выполняется и фаза блокирована:

| Код | Условие |
|---|---|
| DC-F1 | Отслеживаемые файлы входов отличаются от `HEAD`, или материализованный ref не канонический (`AGENTS.md`, «Where the work lives») |
| DC-F2 | State 6 handoff не готов (`design_stage6_contracts.handoff(...)["ready"]` не `True`), или note не привязывается ни к одному модулю M6 |
| DC-F5 | Не читается §15 или файл входа |
| DC-F10 | Инструмент M1–M4 недоступен или вернул ошибку: без резолвера нет L1, без индекса нет L2 |
