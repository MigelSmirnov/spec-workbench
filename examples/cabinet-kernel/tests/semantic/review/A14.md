## Исправления

### `kernel_a14_cancel_owner_only_unended_only` — исправлен
- Было: «завершённый» прогон проверялся только на `failed`. Мутант, считающий завершёнными только `failed` (или только прогоны со спулом), и позволяющий отменить `succeeded` прогон, проходил.
- Стало: добавлен прогон `a14_cancel_failed` с входом `photo-ok`, завершающийся `succeeded`; `cancel_run` → `refused`, `read_run` и трасса не изменились. Мутант M4 теперь падает на `exc.value.code == "refused"` / `read_run(...) == succeeded`.
- Основание: A14 rule 3 «ends a run that has not ended»; Required test 8 «or of a run that has ended»; ended = `succeeded`, `failed`, `refused`, `cancelled` (A13 rule 7; 80_notes `advance_run` [DETERMINISM_OR_ORDERING]); State 5 `runs.cancel_run` Errors: «`refused` for a run that has ended».

## Оставшиеся формальные / ограничения
- Формальных не осталось; `kernel_a14_recovery_completes_before_surface` — частично (ниже).
- `kernel_a14_recovery_completes_before_surface` — частично (почти формальный для своего главного утверждения): восстановление, выполненное лениво внутри первого запроса, а не до открытия поверхности (A14 rule 5; RT «recovery completes before surface»), даёт те же ответы. Ловит его `clock.set(T_RECOVERY)` до `restart()`, `clock.set(T_SURFACE)` после него и проверка, что `ended_at` записи `outcome_unknown` и времена `b_upper` лежат в `[T_RECOVERY, T_SURFACE)`. Правка подготовлена и откачена: таблица «Places the surface cannot reach yet» не даёт этому свидетелю `clock`, а RUNTIME_SURFACE.md менять нельзя. Вход для владельца: дать свидетелю `clock` (и подтвердить, что `clock.set` до `restart()` действует в новом процессе) — тогда добавить проверку.
- `stub.requests` (подсчёт запросов) используется в `kernel_a14_restart_in_flight_becomes_unknown`, `kernel_a14_cancel_empties_spool_keeps_trace`, `kernel_a14_elapsed_wait_changes_nothing`, `kernel_a14_spool_emptied_on_succeeded_refused`, `kernel_a14_recovery_completes_before_surface`; в таблице для этих witness указан `stub_service()` без явного `stub.requests` (для других witness он перечислен отдельно). Это было до ревью; отмечаю для координатора.
- `kernel_a14_resume_without_unreachable_refused`: мутант «Resumption записан до проверки отказа» (State 5 `resume_run`: `record_resumption` first; конвенция «a refusal writes nothing») не наблюдаем — ShownRun не несёт `resumptions`, и вызова для их чтения в RUNTIME_SURFACE нет. Это не смысл Required test 2, только заметка.
