## Исправления

### `kernel_a07_proof_refuses_class_above_accepted` — исправлен
- Было: все рёбра, кроме ребра в `sink.x`, несли класс, равный принимаемому. Мутант, сравнивающий классы по имени (`"open" > "business_confidential"`), этот тест проходил (его ловил только `kernel_a07_inputless_function_output_open`).
- Стало: `_lookup` получил параметр `input_class`; в этом тесте вход `q` обеих привязок принимает `business_confidential` и получает `open`-запрос. Ожидаемый провал не изменился (ребро в `sink.x` — последнее в порядке рёбер); мутант M2 теперь падает на `_edge_key(...) == ("f2","y","sink","x")` и на `control.proof.proven is True`.
- Основание: A07 rule 1 «Classes are ordered `open < business_confidential < personal_data`»; A05 rule 1 phase 8 «does not exceed».

### `kernel_a07_agent_gets_personal_data_as_digest` — исправлен
- Было: `_assert_digest` проверял лишь, что `value_digest` непуст. Мутант, отдающий агенту вместо дайджеста константу, класс или `value_id`, проходил.
- Стало: дайджест `lookup.person` равен дайджесту `f1.x`, `f1.y` — `f2.x`, `f2.n` — выхода прогона `length`; три дайджеста разных значений различны; `value_id` владельца для `lookup.person` и `f2.n` не равен дайджесту агента.
- Основание: A07 rule 4 «it returns only the value's digest and class (K-14), and no `value_id`»; 80_notes `show_port_refs` «ShownValueDigest with the value digest», `compose_flow_version` FIELD_ASSIGNMENT (`value_digest` — content identity байтов, `value_id` — идентичность StoredValueContent).

### `kernel_a07_preview_hides_personal_data_from_agent` — исправлен
- Было: дайджест входа `name` в превью для агента проверялся только на непустоту.
- Стало: дайджест агента `!=` `value_id` того же входа у владельца.
- Основание: A07 rule 4 (как выше).

## Ожидаемые значения
- `open` / `business_confidential` / `personal_data` — DisclosureClass, порядок — A07 rule 1.
- Класс выхода функции — максимум полученного (A07 rule 3, M21); `open` для функции без входов — A07 rule 2 и rule 3 / инвариант `max(...) OR open`.
- Класс выхода привязки — объявленный привязкой (A07 rules 2–3).
- Фаза `disclosure`, ребро провала по порядку рёбер, рёбра в выход потока не проверяются — A05 rule 1 phase 8.
- `value_digest` / `content`, отсутствие `value_id` и `json_text` у агента — ShownValueDigest / ShownContent, A07 rule 4, State 5 «How answers carry values».
- `preview.request is None` для агента при `personal_data`-входе, `request_digest` виден всегда — A07 rule 4, 80_notes `handle_list_records` SECURITY_BOUNDARY.
- Тело `{"name":"Ada Lovelace","topic":"billing"}` — A09 rule 2 (JSON-объект по именам портов, канонический JSON).
