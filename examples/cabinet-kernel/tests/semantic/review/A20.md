## Исправления

### `kernel_a20_ceiling_not_overridable_by_env` — исправлен
- Было: после рестарта с переменными окружения проверялись только `wall_time_ms` и `bounded_text_bytes_max`; ядро, читающее из окружения любой другой потолок, проходило.
- Стало: `_check_ceilings_hold` проверяет «на потолке принято, +1 отказ» для всех четырёх границ ResourceBounds и `page_size_max` (страница `page_size_max` принята, `+1` — `invalid_request`), до и после рестарта.
- Основание: A20 rule 1 «No request, flow, contract, manifest, configuration or environment variable raises one»; A02 rules 1–2; A16 rule 6.

### `kernel_a20_ceilings_equal_release_constants` — исправлен
- Было: второй default искался только по имени, содержащему имя потолка, и только как числовой литерал; `MAX_BODY = 134217728` или `128 * 1024 * 1024` в `service_invoker` проходили; константа провайдера, записанная арифметикой, давала ложный отказ.
- Стало: `_number` вычисляет константную арифметику (`*`, `+`, `-`, `**`, `<<`); вне провайдера запрещены также определения (уровень модуля/класса, умолчания параметров), значение которых равно различимому потолку (30000, 536870912, 67108864, 268435456, 134217728, 60000). Малые и распространённые значения (8, 50, 200, 4096, 16384, 1 MiB) не используются, чтобы не ловить буферы и т. п.
- Основание: A20 rule 1 «no module defines a second default»; `70_data_provider_closure.json` (один дом значений).

## Ожидаемые значения
- Таблица потолков `CEILINGS` = A20 rule 1 (release v1) = `70_data_provider_closure.json` (`RELEASE_CEILING_*`) — сверено.
- `refused` для границы выше потолка: A02 rule 2, 80_notes `issue_contract_version`.
- `invalid_request` для строки выше `bounded_text_bytes_max`, для `page_size > page_size_max` и для запроса выше `surface_request_bytes_max`: A16 rules 1, 4, 6; State 5 таблица кодов; 80_notes `answer_request`.
- `unauthorized` в контроле RT2 (неизвестный токен после проверки размера): A16 rule 1, State 5.
- CPython 3.12 с патч-версией: A20 rule 3 («exact versions … the sandbox interpreter of release v1 is CPython 3.12»).
Все ожидаемые значения следуют из A20, A02, A16 и State 5/6; исправлять значения не потребовалось.

## Оставшиеся формальные / ограничения
- RT1 угадывает имена переменных окружения (`RELEASE_CEILING_X`, `X`, `CABINET_KERNEL_X`, `KERNEL_X`); ядро, читающее переменную с другим именем, не ловится. Статическая проверка «ни один модуль не читает `os.environ`» (A17 rule 1) не добавлена — это не RT A20.
- RT3: потолок, записанный литералом прямо в теле функции (`if size > 200:`), не ловится — локальные литералы не сканируются, чтобы не давать ложных отказов.
- RT4: сопоставление имени импорта и имени дистрибутива (`yaml` ↔ `PyYAML`) нормализацией не решается — возможен ложный отказ при таком пакете; версии bubblewrap тест не требует (ранее рассмотрено, `questions/state2/round-70` T5 — preexisting).
- `release` — то, что объявляет сгенерированный релиз; проверка `release.ceilings == CEILINGS` зависит от того, как фикстура его читает, но константы провайдера проверяются по исходникам независимо.
- Использованы уже перечисленные возможности вне строк таблицы (было до ревью): `installation.agent_token` для `kernel_a20_over_ceiling_refused_not_truncated`.
