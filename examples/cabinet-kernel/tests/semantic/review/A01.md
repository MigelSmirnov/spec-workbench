## Исправления

### `kernel_a01_identity_covers_resource_bounds` — исправлен
- Было: две версии, различающиеся только `memory_bytes`. Мутант, у которого в хеш входит лишь часть полей ResourceBounds (без `wall_time_ms`, `output_bytes` или `process_count`), проходил.
- Стало: от базовой версии по очереди меняется каждое из четырёх полей (удвоение, в пределах потолков A20 rule 1); каждая идентичность отлична от базовой, поле прочитано обратно, все пять идентичностей попарно различны. Мутант M2 падает на `other != first` для выпавшего поля.
- Основание: A01 rule 1 («computed … from the facts State 1 names»), State 6 `ContractVersionContent.resource_bounds: ResourceBounds` (все четыре поля); RT4 «differing only in one resource bound» — для любого из них.

### `kernel_a01_slot_purpose_fixed_at_creation` — исправлен
- Было: проверялась только новая (другая) схема с другой целью. Мутант, который сначала вычисляет идентичность и возвращает существующую равную версию (A01 rule 4), а цель проверяет лишь для новой версии, проходил.
- Стало: добавлен отказ `refused` для равного содержимого (`NUMBER`) с другой целью.
- Основание: A01 rule 5 «This check comes first among the operation's own checks»; State 5 `issue_contract_version` Enforces «Purpose rule first (A01 rule 5)»; 80_notes.md `issue_contract_version` «contract_version_id is computed right after the purpose rule».

### `kernel_a01_flow_purpose_fixed_at_creation` — исправлен
- Было: аналогично, только новое содержимое; мутант «равная версия потока возвращается до проверки цели» проходил.
- Стало: добавлен отказ `refused` для `compose("A01 witness: another purpose", ["a"])` — содержимое равно первой версии.
- Основание: A01 rule 5; State 5 `compose_flow_version` Enforces «Purpose rule first».

## Ожидаемые значения
- `invalid_request` для поля `contract_version_id`: State 5 «Closed set of refusal codes» — `invalid_request`: «unknown field … (A01 rule 1, A16 rules 1, 4, 6)»; `IssueContractVersionRequest` такого поля не имеет.
- `refused` для чужой цели слота/потока: A01 rule 5 + State 5 (`refused` — «an operation's own check failed»; compose_flow_version Errors «`refused` naming … the purpose rule»).
- Идентичность = SHA-256 (lowercase hex) JCS объекта `ContractVersionContent` с `subject_kind`, полями по имени, `None` как `null`, `value_schema` как каноническая строка, порты по (`direction`, `name`): A01 rule 1, State 6 `ContractVersionContent`, 80_notes.md `content_identity` (строки 9–10, 14).
- Порядок `page_records` — новейшие первыми: A16 rule 6; порядок `read_slot` — store order: State 5 `read_slot` Outputs.
- `KernelInstant.epoch_us`, `MINUTE_MS * 1000` мкс: State 6 `KernelInstant`.
- Токен второго автора ≥ 43 символов: A16 rule 1/2. `page_size=200` = `page_size_max` (A20 rule 1).
- Обе реализации допущены одним случаем (2·2 = 2+2 = 4), активация при допуске и «ничего» при повторном откате: A04 rules 4–5, State 5 `roll_back_slot`.
Все ожидаемые значения следуют из A01, State 5 и State 6; исправлять значения не потребовалось.

## Оставшиеся формальные / ограничения
- `kernel_a01_activation_identity_is_store_position`: число записей Activation напрямую не наблюдаемо — `ShownRecords` не имеет `activations`, и State 5 (`50_public_apis.md`, MCP catalogue) говорит «activations are read through `get_slot`», а `read_slot` отдаёт только `serving_activation`. Мутант, который при откате удаляет/переносит старую запись Activation вместо добавления новой (нарушение A01 rule 6), этим тестом не ловится; новой возможности для этого нет.
- `kernel_a01_caller_supplied_identity_refused` использует `installation.agent_token("author")` (для `token=`), а таблица «Places the surface cannot reach yet» для этого witness перечисляет только `mcp_request`. Вызов не нужен по существу: `mcp_request` по умолчанию берёт токен актора (автор для `issue_contract_version`). Решение — за координатором (убрать `token=` или дополнить таблицу).
- Порядок «цель первой среди собственных проверок, но после A02» по причине отказа не проверяется: RUNTIME_SURFACE.md разрешает читать `reason` только там, где решение велит ему что-то назвать (A02 rule 2).
