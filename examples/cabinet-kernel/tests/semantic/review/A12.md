## Ожидаемые значения
- Код `refused` для каждой неудавшейся проверки старта: State 5 `runs.start_run` Errors («`refused` naming the first failing start check — no active version first — no run created»); 80_notes.md `start_run` [VALIDATION_ERROR]. Причина не сравнивается (State 5 Conventions, «Reason»: не машинный идентификатор), поэтому порядок проверок правила 1 через поверхность не наблюдаем — какая проверка сработала, показывают контрольные сценарии.
- `invalid_request` для значения, чей текст сам выше `stored_value_bytes_max`: A16 rule 4 («a value of a trial case or constant, at most `stored_value_bytes_max`, and so is a run's input value (A12 rule 1)», «a field over its bound is refused»), закрытый набор кодов (`invalid_request` — «a field over its bound»). Граница по тексту на поверхности и по каноническому значению в `runs` согласованы: State 5 Conventions «Values enter canonical»; 80_notes.md `start_run` — `fit_port_value` с `JsonCandidate` канонических байтов.
- `STORED_VALUE_BYTES_MAX = 1048576`: A20 (`02_rules_installation.md`, таблица потолков).
- Статусы `awaiting_approval`, `succeeded` (RunStatus); причина ожидания `owner_approval` (WaitReason); `executed.binding_id` / `executed.implementation_id` (ExecutedBinding / ExecutedImplementation, M23); `output_kind == "produced"` (ShownProducedOutput); фильтры `flow_version_id` для `run` и `run_id` для `node_execution` (каталог MCP, `list_records`).
- Все ожидаемые значения следуют из A12, A16 rule 4, A20, State 5 и State 6.

## Оставшиеся формальные / ограничения
- Формальных тестов нет.
- Порядок проверок правила 1 («in this order ... the first that fails») не проверяется: отказ различим только по `reason`, который тесты не читают (RUNTIME_SURFACE.md, «Refusal reason»: только где решение велит причине что-то называть). Это не требование Required tests 1 и 4.
- RT3 («Two runs on equal inputs have distinct identities and traces») не несёт тега witness — теста нет.
- Способности: `kernel_a12_pins_survive_later_records` использует только перечисленные в таблице (`manifest.write_record`, `installation.select_instance`, `installation.set_credential`, `stub_service()`, `clock.advance`); два других теста способностей не используют.
