## Исправления

### `kernel_a03_fresh_env_no_network_no_host_mounts` — исправлен
- Было: `len(executions) >= 5`. Пробное исполнение при старте (A03 rule 8) тоже есть в `sandbox_executions()`, так что мутант, исполняющий узел прогона быстрым путём в процессе, давал 5 и проходил, хотя комментарий теста утверждает «A03 rule 1 holds for trial and run alike».
- Стало: после выпуска контракта и добавления случаев (ядро уже стартовало) берётся `baseline`. После допуска и `try` ожидается `baseline + 4`, после прогона `baseline + 5`. Мутант M4 (и такой же для испытаний) падает.
- Основание: A03 rule 1 «Every function execution, in trial and in a run alike, runs in a fresh isolated environment … There is no in-process or fast path.»

## Ожидаемые значения
- Исходы `passed`, `timeout`, `resource_exhausted`, `sandbox_violation`, `crashed`, `contract_violation` взяты из State 6 TrialOutcome. Порядок взят из A03 rule 5 и SandboxOutcome; `succeeded` песочницы — это `passed` случая без ожидаемых выходов (80_notes `execute_trial_case`).
- `reason_kind == "failing_case"` и `reason.outcome` — State 6 FailingCaseRefusal, A04 rule 3.
- Граница выхода: `n` символов → `n + 2` байт канонического JSON. Учитывается только значение (A03 rule 5: «canonical JSON bytes of every `value` output»). `resources_used.output_bytes` — это счёт выхода (80_notes `execute_function` [RETURN_SHAPE]).
- Fork-цикл → `resource_exhausted`: решение владельца 2026-10-06 (HANDOFF_20260929.md; 80_notes `execute_function`, `process_count`), не вопрос.
- `MemoryError`, вылетевший из `run`, → `resource_exhausted` (80_notes, owner 2026-10-06).
- `internal_error` при неподтверждённой очистке — State 5 Conventions «Stop required». `detail_code == "cleanup_failed"` — State 5, закрытый набор деталей, DetailCode.
- Остановленный старт: `started False`, ненулевой код выхода, причина в stderr — State 5 `surface.serve_kernel` Outputs.
- `{"PYTHONHASHSEED": "0"}` — A03 rules 1–2, RT9.
- Все ожидаемые значения следуют из A03 и State 5/6; ни одно значение не менялось.

## Оставшиеся формальные / ограничения
- `kernel_a03_unloadable_module_is_crashed` — частично: мутант M3 (ядро само делает `compile`/`ast.parse`, ловит `SyntaxError` и пишет `crashed`, не запуская песочницу; нарушает RT4 «Submitting code never compiles, imports or parses it» и A16 rule 5) даёт те же ответы. Поймать его можно проверкой `len(sandbox_executions())` до/после (+2: случай допуска и `try`), но таблица «Places the surface cannot reach yet» не даёт `sandbox_executions()` этому свидетелю, а RUNTIME_SURFACE.md менять нельзя. Правка подготовлена и откачена; вход для владельца: дать свидетелю `sandbox_executions()` (строка таблицы) — тогда добавить проверку.
- `kernel_a03_fresh_env_no_network_no_host_mounts`: `mounts` — это только пути хоста. Мутант, который монтирует runtime на запись (а не только для чтения), этим тестом не ловится: нужен атрибут режима монтирования, которого в `sandbox_executions()` нет. Также не видны пространства имён user/PID/IPC/UTS (rule 1). Это ограничение поверхности.
- `kernel_a03_trap_hit_is_sandbox_violation` проверяет только четыре точки входа из RT1. Полнота закрытого списка rule 4 этим witness не покрывается и по RT1 не требуется.
- RT6 (детерминизм) без witness-тега — теста нет.

## Вопросы владельцу

1. **Считается ли loopback `lo` «сетевым интерфейсом» (RT10)?** A03 rule 1: «Linux `bubblewrap` with new user, PID, IPC, UTS and network namespaces, no network interface». RT10: «each execution's environment has no network interface». Тест проверяет `assert not observed.network_interfaces`. Но новый сетевой namespace всегда содержит `lo`, а `bubblewrap --unshare-net` сам поднимает в нём loopback (127.0.0.1). Отключить это опцией bwrap нельзя. Нужен выбор:
   (а) `lo` считается интерфейсом. Тогда ядро обязано убрать или опустить loopback внутри окружения, а тест остаётся как есть;
   (б) «no network interface» означает «нет интерфейса, кроме loopback». Тогда тест должен допускать `lo` (например, `set(observed.network_interfaces) <= {"lo"}`), а формулировку rule 1 / RT10 стоит уточнить.
   Тест не менялся.
