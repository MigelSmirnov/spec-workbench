## Исправления

### `kernel_a08_non_read_key_field_must_be_input_port` — исправлен
- Было: один отклоняемый вариант — `material_id` не является портом вообще. Мутант, сверяющий ключевые поля с именами портов любого направления, проходил.
- Стало: отклонение проверяется в двух вариантах: `material_id` отсутствует среди портов и `material_id` — выходной порт. Мутант M2 падает на втором варианте (`pytest.raises`). Контроль без изменений.
- Основание: A08 rule 4 «each name must equal the name of one `value` input port of the proposal»; rule 5 «a key field of rule 4 is not a `value` input port of the proposal». RT2 («key field `material_id` is not an input port») — смысл не меняется: выходной порт тоже не входной порт.

### `kernel_a08_record_read_only_at_pinned_path` — исправлен
- Было: для `Drafts` и `nested/drafts` инстанс не выбирался. Правило 5 ставит «the installation selects no instance for the service» после проверок записи, поэтому ядро без проверки синтаксиса `service_id` (правило 1) всё равно отказывало — по отсутствию инстанса. Комментарий «only the identity check can refuse these» был неверен, и в этой части тест был формальным.
- Стало: `_select` вызывается и для `Drafts`, и для `nested/drafts`. Теперь запись по сырому пути существует, поле `service` совпадает, инстанс выбран, и единственная проверка, которая может отказать, — синтаксис идентификатора. Мутант M4 падает на `pytest.raises`.
- Основание: A08 rule 1 «any other is refused before a path is built»; rule 5 (порядок проверок). Конфигурация установки синтаксис `service_id` в `service_instances` не проверяет (80_notes.md, `read_configuration` [VALIDATION_ERROR]), так что такая установка запускается.

## Ожидаемые значения
- Код `refused` для всех отказов предложения: State 5 `propose_binding` Errors («`refused` naming the first failing check»); причина не сравнивается, потому что State 5 Conventions, «Reason»: «not a machine identifier». Какое правило сработало, показывает контрольный сценарий.
- `status` `proposed` / `accepted`: M11, State 5 (`propose_binding`, `accept_binding`).
- `effect_class` и `idempotency_key_fields` копируются из манифеста: A08 rule 5 (последнее предложение), M11.
- `operation_failed` + `binding_stale`, без EffectAttempt: A08 rule 6, A09 rule 6, State 5 «Details of an element that concluded `operation_failed`».
- `attempt_number == 1`: A11 rule 1. Run `failed`: A13 rules 5, 7.
- Правка `note` своей записи меняет дайджест: A08 rule 2 и 80_notes.md `read_service_record` [FIELD_PROJECTION] — «content_identity of the canonical JSON of that one raw capability entry».
- `draft-write` отправляется без одобрения (`succeeded` в первом запуске): A10 rule 1.

Все ожидаемые значения следуют из A08 rules 1–7, A09 rule 6, A10 rule 1, A13 rule 7, State 5 и 80_notes.md; исправлять значения не пришлось.

## Оставшиеся формальные / ограничения
- Формальных тестов не осталось.
- Ограничение для RT1, RT6 и RT7: в RT сказано «naming rule 3» / «naming the absent record» / «naming that check», но причина отказа не является машинным идентификатором (State 5, «Reason»), поэтому названную проверку тест не сверяет. Её заменяет контрольный сценарий. Мутант, который вместо правила 3 отказывает по более поздней проверке (например, по форме запроса без метода), наблюдаемо неотличим.
- RT2: мутант, принимающий как ключевое поле входной порт с `carriage: "file"` (правило 4: «a file is never a key field»), не покрыт. Это за пределами формулировки RT2, поэтому сценарий не добавлялся.
- В RT6 теперь выбираются инстансы для невалидных `service_id` (`Drafts`, `nested/drafts`) через `installation.select_instance`. Эта возможность уже указана для этого witness, но координатору стоит знать, что фикстура должна принимать такой `service_id` в конфигурации.
- RT3 читает `stub.requests`. В таблице «Places the surface cannot reach yet» для `kernel_a08_digest_covers_only_own_capability_entry` указан `stub_service()`, а `stub.requests` отдельно не назван (для RT4 он назван). Решает координатор.
- A08 RT5 (заявленный в предложении класс эффекта отклоняется) не имеет witness, поэтому теста нет.
