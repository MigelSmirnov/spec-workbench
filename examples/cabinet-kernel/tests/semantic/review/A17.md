## Исправления

### `kernel_a17_config_file_owner_only` — исправлен
- Было: проверялись режимы `0o604` и `0o640` — оба с правом чтения; мутант, проверяющий только биты чтения (`mode & 0o044`), проходил.
- Стало: дополнительно `0o620` (запись группе) и `0o601` (исполнение прочим) должны не запускаться; мутант «только биты чтения» (и «только чтение/запись», `& 0o066`, на `0o601`) падает на `started is False`.
- Основание: A17 правило 1: «owned by the kernel's user, with no permission for group or others; the kernel refuses to start otherwise»; формальный инвариант `config_file_mode -> owner_only_readable`. Смысл RT2 («readable by others stops the start») сохранён — проверки RT2 остались.

### `kernel_a17_credential_resolved_per_request` — исправлен
- Было: проверялось только «после записи файла следующий запрос несёт значение»; ядро, кэширующее первое разрешённое значение, проходило.
- Стало: после перезаписи секрета (`write_secret("service_a", CANARY_ROTATED)`) следующий запрос несёт новое значение; мутант с кэшем падает на `_header_values(stub_a.requests[1], ...) == [CANARY_ROTATED]`.
- Основание: A17 правило 2: «A credential is resolved only when a request to its service is built: its secret file is read then»; инвариант `credential_resolved -> at_request_build`; A10 правило 7 («rotating it voids no approval»).

### `kernel_a17_canary_credential_never_written`, `kernel_a17_echoed_credential_body_withheld` — усилены (не были формальными)
- Было: отсутствие канарейки в `store_dump()` / `surface_answers()` проверялось без проверки, что наблюдатели вообще что-то захватили; пустой захват фикстуры делал утверждения пустыми.
- Стало: контроль — `run.run_id` присутствует в `store_dump()` и `surface_answers()`, `process_arguments()` непуст (только в RT1).
- Основание: RT1/RT4 требуют отсутствия в «store record … response»; брифинг — исход не должен решаться фикстурой.

## Ожидаемые значения

- Заголовок превью `x-api-key` по имени, `value is None` — A10 правило 7 (имена в нижнем регистре, учётные данные только по имени); State 6 `DescribedHeader.value: str | None`.
- `awaiting_approval`, `owner_approval` — A10 правила 1–2, State 6 `RunStatus`/`WaitReason`.
- `operation_refused` на 409 и тело как `failure_detail` — A09 правила 5, 7.
- `contract_violation`, ноль выходов, `failure_detail` ровно `error body withheld: it contained the credential` — A09 правила 5, 7; A17 правило 2.
- Run `failed`, один `missing` выход `note` с `not_produced` — A13 правила 5, 7; State 6 `MissingOutput`/`OutputReason`.
- `operation_failed` + `credential_unresolved` для сервиса без учётных данных / с отсутствующим файлом — A17 правило 2, A09 правило 6, State 5 детали `operation_failed`, State 6 `DetailCode`.
- `invalid_request` для поля `instance_name` — A16 правило 4, State 5 коды; State 6 `ProposeBindingRequest`/`FlowNode`/`StartRunRequest` не имеют такого поля.
- Значение входа в сегменте пути percent-encoded, запрос идёт на выбранный экземпляр — A09 правила 1–2.
- Ненулевой код выхода при отказе старта — A17 правило 1 («refuses to start»).

Все ожидаемые значения следуют из A17, A09, A10, A13, A16 и State 5/6; исправлять нечего.
