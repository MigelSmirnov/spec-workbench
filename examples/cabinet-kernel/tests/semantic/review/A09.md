## Ожидаемые значения
- Таблица исходов A09 rule 5: `outcome_unknown` / `unknown` для обрыва после записи у не-read; `service_unreachable` для `read` при 5xx, отказе и обрыве; `operation_refused` / `not_applied` для 4xx; `contract_violation` / `applied` для невалидного 2xx и для 2xx с эхом (rule 7, owner 2026-10-05); `operation_failed` для `read` при 3xx с деталью `redirect_not_followed` (State 5, закрытые детали).
- `plain_http_not_allowed` без EffectAttempt: A09 rules 4, 6.
- Run `pending` и ожидания `service_unreachable` / `outcome_unknown`: A13 rules 5, 8; WaitReason. Run `failed` при `operation_refused` / `contract_violation` / `operation_failed`: A13 rules 5, 7.
- `attempt.authority.authority_kind == "flow_activation"`: A10 rule 6, ActivationAuthority. У `read` нет EffectAttempt: A10 rule 6.
- `resume_run` без элементов `service_unreachable` → `refused`: A14 (инвариант `resume AND none_waiting_unreachable -> refused`, RT2).
- `failure_detail` = `"error body withheld: it contained the credential"` (rule 7); текст тела 409/401 хранится как DetailText (класс `open`, читает владелец, A07 rule 5).
- `MissingOutput` с `output_kind == "missing"`: ShownRunOutput, A13 rule 7.

Все ожидаемые значения следуют из A09 rules 1–7, A10 rule 6, A13 rules 5, 7, 8, A14 и State 5/6.

## Оставшиеся формальные / ограничения
- `kernel_a09_read_unsent_or_unanswered_unreachable` (частично): повтор попытки соединения после отказа (A09 rule 1: «nothing is retried inside one attempt») не наблюдается. `stub_service().requests` фиксирует только принятые запросы, а счётчика попыток соединения в RUNTIME_SURFACE.md нет. RT9 требует «no second request», а отказанное соединение запросом не является, поэтому формулировка RT выполнена, но такой мутант проходит.
- `kernel_a09_no_redirect_plain_http_restricted`: «другой хост» редиректа задан как `localhost:<порт второй заглушки>` — другое имя и порт, при этом loopback. Внешний хост заглушкой не воспроизводится.
- A09 RT6 (переменная прокси) не имеет witness, поэтому теста нет.
