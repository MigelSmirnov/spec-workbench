## Исправления

### `kernel_a02_bound_at_ceiling_ok_over_refused` — исправлен
- Было: `assert field in exc.value.reason` и пустой список версий. Причина вида «bounds wall_time_ms, memory_bytes, output_bytes, process_count must be within ceilings» проходила для любого поля; запись слота до отказа не замечалась.
- Стало: `_assert_names_only(reason, field)` — названо поле, нарушившее границу, остальные три поля не названы; `_assert_nothing_recorded` — нет ни версии, ни слота.
- Основание: A02 rule 2 «The refusal names the field and the ceiling»; A02 rule 1 «When several conditions fail, the first in this list is named»; State 5 Conventions «A refusal is decided before the operation's first store change, so it writes nothing»; State 5 «Named store changes»: `issue_contract_version` пишет ContractVersion и Slot (когда новый) одним изменением.

### `kernel_a02_absent_bound_refused` — исправлен
- Было: `"memory_bytes" in reason`, пустой список версий.
- Стало: `_assert_names_only(reason, "memory_bytes")`, `_assert_nothing_recorded`.
- Основание: A02 rule 2 («A bound omitted by the author is refused as well»), State 5 `issue_contract_version` Errors «`refused` naming the first failing check, with field and ceiling for a bound»; State 5 Conventions (отказ ничего не пишет).

### `kernel_a02_zero_bound_refused` — исправлен
- Было/стало: как в двух предыдущих — названо только нулевое поле; ни версии, ни слота.
- Основание: A02 rule 1 («every field of ResourceBounds M04 is a positive integer…»), State 5 Errors, Conventions.

Тесты `output_disclosure_class_refused`, `no_output_port_refused`, `port_names_unique_per_direction` уже ловили мутанты своего инварианта; в них лишь проверка «ничего не записано» заменена общим `_assert_nothing_recorded` (версия и слот).

## Ожидаемые значения
- Потолки `wall_time_ms` 30000, `memory_bytes` 536870912, `output_bytes` 67108864, `process_count` 8 — A20 rule 1 (release v1), 80_notes.md `issue_contract_version` (`RELEASE_CEILING_*`).
- Код `refused` во всех отказах: State 5 `issue_contract_version` Errors; пропущенное поле допустимо по схеме (`ResourceBoundsRequest` — `int | None`), поэтому это не `invalid_request`.
- Имя поля в причине: A02 rule 2, State 5 Errors; RUNTIME_SURFACE.md «Refusal reason» (A02 rule 2: the field).
- Контроль `1` для каждого поля: A02 rule 1 — положительное целое, нижней границы нет.
- `disclosure_class is None` на выходе: A02 rule 1 / M01.
- `page_records("slot", None)`: State 5 MCP catalogue — для slots фильтров нет; `page_size=200` = `page_size_max` (A20 rule 1).
Все ожидаемые значения следуют из A02, A20 rule 1 и State 5/6; исправлять значения не потребовалось.

## Оставшиеся формальные / ограничения
- Потолок в причине (A02 rule 2: «names the field and the ceiling»; State 5: «with field and ceiling for a bound») не проверяется: RT1 требует только поле, RUNTIME_SURFACE.md разрешает читать `reason` лишь для поля, а форма записи потолка в тексте не задана.
- Мутант «нарушено правило порядка проверок A02 rule 1 (называется не первое из нескольких нарушенных условий)» не проверяется: ни один Required test этого не требует.
- Required test 4 без witness — теста нет (см. SUMMARY.md, «Required tests без witness»).
