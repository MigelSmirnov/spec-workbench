## Исправления

Нет. Подготовленная правка `kernel_a13_one_node_executes_at_a_time` (`started_at < ended_at` для каждой записи) откачена: часы ядра инжектирует фикстура, и при стоящих часах верная реализация даёт `started_at == ended_at` — проверка решалась бы фикстурой, а `clock` этому свидетелю таблицей RUNTIME_SURFACE.md не дан.

## Ожидаемые значения
- Порядок по кодовым точкам (`Z` < `a`) — A13 rule 2, A05 rule 2.
- `/items?x=N` — A09 rule 2 (GET, параметр запроса, целое как канонический JSON).
- `skipped_by_guard`, `upstream_failed`, `crashed`, `succeeded` — NodeExecutionStatus; `crashed` для исключения — A03 rule 5.
- `not_produced` / `skipped_by_guard` у выходов — OutputReason, A13 rule 7; `output_kind` `produced` / `missing` — ShownRunOutput.
- `awaiting_approval` / `pending` — A13 rule 8; `succeeded` / `failed` — A13 rule 7.
- `upstream_failed` у `c` после `applied` для связки с выходами — A11 rule 3, A13 rule 5.
- `refused`-код не используется. Значения `8`, `22`, `-1`, `"duplicate"` следуют из кода функций теста.

Все ожидаемые значения следуют из A13, A11, A09, A05, A03 и State 5/6.

## Оставшиеся формальные / ограничения
- `kernel_a13_resolved_unknown_conclusion` — формальный (skip) до решения известного вопроса A13 RT9.
- `kernel_a13_one_node_executes_at_a_time` — частично: мутант «два узла параллельно, обе записи с временем записи» (A13 rule 2 «Nodes execute one at a time») проходит, а M1 ловится, только если часы фикстуры идут во время исполнения. Без `clock` у свидетеля (например, часы, сдвигаемые на каждом чтении) различить нельзя; вход для владельца — дать свидетелю `clock` или наблюдение `sandbox_executions()` с временами.
- `kernel_a13_advance_only_inside_request`: фоновый поток, срабатывающий по реальному времени асинхронно, ловится лишь если успевает до второго `_snapshot`; через поверхность сильнее не выразить.
- Все использованные capabilities перечислены в таблице «Places the surface cannot reach yet» для своих witness.
