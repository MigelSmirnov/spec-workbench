## canonical_values

fit_port_value: [DEPENDENCY_BOUNDARY] Like every function of its module it is pure: it reads no file, no clock, no environment and no store, writes nothing, and decides nothing about what a failed fit or a refused value means for its caller.
canonical_bytes: [BEHAVIOR] MUST parse json_text as one JSON value and emit its RFC 8785 (JCS) canonical form encoded as UTF-8: object members sorted by the UTF-16 code units of their names, numbers written in the ECMAScript shortest round-trip form (an integral double without a fraction or exponent, so a number written 1.0 becomes 1), strings escaped exactly as JCS prescribes, and no whitespace; it applies no Unicode normalization, so two texts that differ only in normalization give different bytes.
canonical_bytes: [VALIDATION_ERROR] MUST raise NonCanonicalValueError, with a reason naming the first offending item in text order, when json_text is not one well-formed JSON value, when an object repeats a member name at any depth, when it holds a non-finite number (NaN, Infinity or -Infinity tokens, which the default Python parser would accept and therefore MUST be rejected explicitly), when a number written without a fraction or exponent lies outside plus or minus (2 to the power 53 minus 1), which an IEEE double cannot hold exactly, or when a string holds a lone surrogate.
canonical_bytes: [RETURN_SHAPE] Returns the canonical UTF-8 bytes only; the length of these bytes is the size of the JSON value wherever the kernel measures a value.
content_identity: [BEHAVIOR] For every content variant of IdentitySubject (contract_version, implementation, trial_case, flow_version, stored_value, corpus) MUST build one JSON object whose members are exactly the variant's fields keyed by field name, subject_kind included, with nested models as objects keyed by field name, tuples as arrays, enum members as their value text, None as null and JSON-text fields such as value_schema kept as JSON strings, take its canonical bytes with canonical_bytes and return the lowercase hexadecimal SHA-256 of those bytes.
content_identity: [DETERMINISM_OR_ORDERING] Before hashing, lists whose order carries no meaning MUST be sorted so that the same content in another order has the same identity: ports by (direction, name), flow nodes by node_id, flow edges by (to_node, to_port, from_node, from_port), flow constants by (to_node, to_port), all compared as text by Unicode code point; every other list keeps its order, in particular trial_case_ids of a corpus (corpus order is meaningful) and the elements of any JSON value.
content_identity: [BEHAVIOR] For the idempotency_key variant MUST build one JSON object with one member per entry of fields, named by the entry's port and holding the JSON value its canonical_json encodes, so the order of the fields does not change the key, and return the hexadecimal SHA-256 of its canonical bytes; a field whose value is null is kept as null, not dropped.
content_identity: [BEHAVIOR] For the json_text variant MUST return the hexadecimal SHA-256 of the canonical bytes of json_text, and for the bytes variant the hexadecimal SHA-256 of content exactly as given, without any canonicalization; this is the digest of a file and of a value's bytes.
content_identity: [VALIDATION_ERROR] MUST let NonCanonicalValueError from canonical_bytes propagate unchanged when any JSON text the subject carries cannot be represented canonically; it computes no partial identity.
content_identity: [RETURN_SHAPE] Returns the 64-character lowercase hexadecimal SHA-256 digest as text.
fit_port_value: [DETERMINISM_OR_ORDERING] MUST judge the candidate against the port with the checks in exactly this order and stop at the first that fails: presence (candidate is None), carriage, schema, size; within one check the elements of a list are judged in list order and the reason names the index of the first failing element.
fit_port_value: [BEHAVIOR] Carriage fits when a port of = models.Carriage value receives a json candidate, a file port of = models.Cardinality one receives a file candidate, and a file port of cardinality many receives a file_list candidate; any other pairing fails the carriage check.
fit_port_value: [SCHEMA_CONSTRAINT] The schema check of a value port parses the port's value_schema and the candidate's canonical_json; for cardinality many the candidate MUST be a JSON array and every element MUST fit the schema, for cardinality one the whole value MUST fit it. Supported schema keywords are only type (one of null, boolean, integer, number, string, array, object, given as one string), enum (non-empty array of distinct scalars), const (one scalar), properties and required for objects, additionalProperties given as true or false only, items (one schema) for arrays, minItems, maxItems, minLength, maxLength, minimum and maximum; integer means a number without a fraction; a schema that is not a JSON object or uses any other keyword ($ref, pattern, format, oneOf, anyOf, allOf and not among them) fits no value, so the schema check fails.
fit_port_value: [SCHEMA_CONSTRAINT] A file's content is never opened or inspected: the schema check of a file port compares each candidate file's media_type with the port's media_type as exactly equal text, and the size check compares each file's size_bytes with size_bound per file, never their sum.
fit_port_value: [BEHAVIOR] The size check of a value port compares the length of the candidate's canonical_json, taken as the whole value even for cardinality many, with size_bound and fails when it is larger; size_bound is whatever ceiling the caller passes and the function never chooses one itself.
fit_port_value: [RETURN_SHAPE] Never raises for a candidate that does not fit: returns PortFit with fits true, failed_check None and reason None, or with fits false, failed_check the first failing = models.FitCheck member and a reason naming the port and, for a list, the failing element index.
highest_disclosure_class: [BEHAVIOR] MUST return the highest member of classes by the declared order of = models.DisclosureClass (open, then business_confidential, then personal_data) and open when classes is empty; no input ever lowers the result.
highest_disclosure_class: [RETURN_SHAPE] Returns one DisclosureClass member.

## store

record_change: [DEPENDENCY_BOUNDARY] Its module is the only code that opens the SQLite database, begins, commits or rolls back a transaction, or touches the data directory; callers never open, name or pass a transaction, and every module reaches records and bytes only through this module's functions.
record_change: [DEPENDENCY_BOUNDARY] Every row MUST be read and written only through the StoreRepository operations of one SqliteStoreRepository that the module builds over its own connection inside the transaction it began; the module sends no SQL of its own beyond beginning, committing and rolling back that transaction and setting the connection's synchronous mode, and never creates a table itself.
record_change: [FIELD_ASSIGNMENT] Each record MUST be written as the row model named after it (SlotRow for a Slot, RunRow for a Run, and so for every record type) with store_position the record's store position, record_type the = models.RecordType member of its kind, its key and lookup fields copied from the record — element the record's ElementKey of run_id, node_id and map_index, attempt its AttemptKey with attempt_number, file a SpooledFile's SpooledFileKey, executed_implementation_id the implementation_id of an executed implementation and executed_binding_id the binding_id of an executed binding (each None otherwise), and flow_id of a FlowActivation the flow_id of the FlowVersion it activates — and record the record itself; a new record is added with the row's insert operation, and a lifecycle change rewrites the existing row with its update operation, which keeps the row's store_position.
record_change: [PATH_OR_ARTIFACT_POLICY] Every file and directory under the data directory MUST be opened without following symbolic links; a symbolic link met by any call after start makes that call raise StoreInternalError with nothing written.
record_change: [DETERMINISM_OR_ORDERING] Every record written gets one store position from next_store_position, a single strictly increasing counter shared by all record types, called inside the transaction that writes the record; store order is the order of these positions, every collection the module returns is in store order unless the function says otherwise, and Activation and FlowActivation records are identified by their store_position.

advance_run: [BEHAVIOR] A mapped node over an empty list executes and sends nothing and writes one NodeExecution succeeded without map_index, executed naming its pinned implementation or binding, every output an empty list of the empty list's class: a value output a StoredValuesRef to the StoredValue of [] published with put_value_bytes and written in the same change, a file output an empty SpooledFilesRef; a mapped node concludes only when every element concluded, succeeded only when all succeeded.
advance_run: [ORCHESTRATION] After each function element — except one crashed with cleanup_failed, which its own note handles — MUST write one RecordRunProgressChange through record_change with the given actor, holding that element's execution, its StoredValues and SpooledFiles, and every skipped_by_guard and upstream_failed record that became determined, executions sorted by (node_id, map_index), with status running; after an operation element, whose concluding record effects wrote, the next RecordRunProgressChange holds the records it made non-executable.
advance_run: [VALIDATION_ERROR] When a function element's outcome is crashed with detail cleanup_failed MUST write that one execution in a RecordRunProgressChange with status running and the waiting points unchanged, execute and reach nothing more, write no other status, and raise StopRequiredError.
advance_run: [BEHAVIOR] When nothing can execute: if any element waits, the run rests awaiting_approval when one waits with reason owner_approval, otherwise pending, with one WaitingPoint per waiting element; if nothing waits, the run ends succeeded when every node concluded succeeded or skipped_by_guard and failed otherwise, a mapped node whose delivered value list is over the stored value ceiling counting as failed by the same derivation, with no record of its own, with ended_at set and no waiting points. The final change carries the produced flow outputs as PortRefs, each a StoredValuesRef, since a flow output is never of file carriage (A05 rule 7: composition refuses a flow input or output of file carriage), so a mapped node's file output reaches only node inputs; after a change that ends the run succeeded or refused MUST call remove_run_spool for the run and ignore its StoreInternalError.
advance_run: [RETURN_SHAPE] Returns derive_run_answer of the run as it now rests or ended.

execute_function_element: [ORCHESTRATION] MUST read the pinned implementation of the node with read_implementation, read every input's bytes with read_value_bytes into PortPayloads by port, take started_at from kernel_now, and call execute_function with the code, the payloads, the contract version's input and output ports and its resource_bounds; it writes no record and returns the outcome for its caller to write.
execute_function_element: [BEHAVIOR] On an outcome other than succeeded the NodeExecutionDraft carries that outcome as status with the SandboxResult detail_code, failure_detail and resources_used, executed the ExecutedImplementation, the input PortRefs and no outputs. On succeeded, each JSON output above the imported RELEASE_CEILING_STORED_VALUE_BYTES_MAX constant concludes contract_violation with detail value_too_large, the SandboxResult's resources_used and no outputs; otherwise JSON outputs are published with put_value_bytes — each value_digest is content_identity of a BytesContent holding the bytes and value_id content_identity of the StoredValueContent — as StoredValues of the port's stored schema (M21: its value_schema, or for a many port the canonical array schema with it as items), and files are published with spool_file under the run, node, map_index, the element's next attempt_number — the count of its NodeExecutions read with ExecutionsOfElement plus one, the number its record is then written under — the port and the list_index for a many port, a RefusedError from spool_file concluding resource_exhausted with the SandboxResult's resources_used and no outputs; spool_file's refusal has itself removed the files of that attempt, so nothing is left to clean.
execute_function_element: [RETURN_SHAPE] Returns FunctionElementOutcome with the NodeExecutionDraft, whose ended_at is taken when the outcome is built, and the StoredValues and SpooledFiles of its outputs, each of the class highest_disclosure_class gives for the classes of every input value and file the element received — an input file list counting with its SpooledFilesRef's disclosure_class, even when empty — and each output SpooledFilesRef with that same class, so no output is of a lower class than an input.

derive_run_answer: [BEHAVIOR] MUST compute the answer from the Run record and its trace each time it is asked and store nothing: the status as recorded, the produced flow outputs, and one RunWait per WaitingPoint in (node_id, map_index) order carrying, for reason owner_approval, the approval_id that operation_element_conclusion gives.
derive_run_answer: [FIELD_PROJECTION] Outputs are in flow output port name order: a ProducedOutput with the value_id of its StoredValuesRef for every produced output, a flow output being of value carriage (A05 rule 7); for a run that has ended, a MissingOutput for every other output with reason skipped_by_guard when every edge into it was disabled by its guard or comes from a node recorded skipped_by_guard and not_produced otherwise (= models.OutputReason); a run that has not ended lists only produced outputs.
derive_run_answer: [RETURN_SHAPE] Returns RunAnswer with the Run's run_id, flow_version_id, status, started_by, started_at, ended_at, cancelled_by, released_by and released_at.

read_run: [VALIDATION_ERROR] MUST read the Run by identity through read_records with RecordsById, letting UnknownReferenceError propagate for a run that does not exist.
read_run: [RETURN_SHAPE] Returns derive_run_answer of that run; it writes nothing.

cancel_run: [VALIDATION_ERROR] MUST read the Run by identity, UnknownReferenceError propagating, and raise RefusedError naming its status when the run has ended.
cancel_run: [BEHAVIOR] MUST write one RecordRunProgressChange through record_change with the given actor, with no executions, status cancelled, no waiting points, the produced outputs and ended_at, so that nothing further is sent and undecided approvals can no longer be decided; an unknown EffectAttempt stays unknown and every concluded record stays. Then MUST call remove_run_spool for the run, ignoring its StoreInternalError: from the cancellation on the run's spool can no longer be read, and files whose removal fails here are removed at the next start; return derive_run_answer of the cancelled run.

release_run: [VALIDATION_ERROR] MUST read the Run by identity, UnknownReferenceError propagating; then raise RefusedError when its status is not failed, and RefusedError when released_by is already set.
release_run: [BEHAVIOR] MUST write one ReleaseRunChange through record_change with the given actor, with released_at, then call remove_run_spool for the run, ignoring its StoreInternalError, and return derive_run_answer showing released_by and released_at.

resume_run: [VALIDATION_ERROR] MUST read the Run by identity, UnknownReferenceError propagating, and raise RefusedError when no element of the run waits with reason service_unreachable, an ended run included.
resume_run: [ORCHESTRATION] MUST write one RecordResumptionChange through record_change with the given actor first, then reach again with reach_operation_element every element waiting with reason service_unreachable in (node_id, map_index) order with its current inputs, and only after all those resends advance the run with advance_run and return its answer; elements waiting with reason owner_approval or outcome_unknown are not touched.

continue_after_approval: [VALIDATION_ERROR] MUST read the EffectApproval by identity with RecordsById to find its run, UnknownReferenceError propagating; then read its Run and raise RefusedError when the run has ended; then call decide_effect_approval, whose RefusedError propagates.
continue_after_approval: [ORCHESTRATION] After an approve decision MUST reach the approval's element again with reach_operation_element in this request, then advance the run with advance_run; after a refuse decision MUST reach nothing and advance the run with advance_run, which ends it refused; returns the run's answer.

continue_after_resolution: [VALIDATION_ERROR] MUST read the EffectAttempt of the AttemptKey with RecordsByAttempt to find its run, UnknownReferenceError propagating; then read its Run and raise RefusedError when the run has ended; then call resolve_unknown_outcome, whose RefusedError propagates.
continue_after_resolution: [ORCHESTRATION] After a not_applied resolution MUST reach the element again with reach_operation_element, which requests a fresh approval even where a grant exists, and then advance the run with advance_run; after an applied resolution MUST advance the run with advance_run; advancing runs every element that becomes ready and sends its requests under the authority each has; returns the run's answer.

recover_running_runs: [ORCHESTRATION] MUST first call remove_run_spool for every run that has ended and keeps no spool — status succeeded, refused or cancelled, or failed with released_by set — ignoring a StoreInternalError of each removal; then MUST read every run that has not ended with one RunsByStatus naming running, awaiting_approval and pending (= models.RunStatus), whose answer is already oldest first in store order; each is derived again from its records under an Actor of kind kernel: a stored status or waiting point that lags them (an approval already decided, an attempt already resolved, an outcome whose run change was lost) is rewritten, an operation element whose wait no longer holds is reached again through reach_operation_element, and every run the derivation leaves running is advanced with advance_run.
recover_running_runs: [RETURN_SHAPE] Returns the number of runs advanced; a StopRequiredError or a failed store change propagates and stops the start.

capture_failed_execution: [VALIDATION_ERROR] MUST read the NodeExecution of the AttemptKey with RecordsByAttempt, UnknownReferenceError propagating; then raise RefusedError unless its executed is an ExecutedImplementation, its resources_used is present (the function ran in the sandbox; a receiving node that refused a misfit input did not) and its status is not succeeded; then read its Run and raise RefusedError unless the run has not ended, or ended failed with released_by absent.
capture_failed_execution: [ORCHESTRATION] MUST copy nothing itself: after its own checks it calls add_captured_trial_case with the implementation_id of the record's ExecutedImplementation, the named contract version, the record's inputs as they are — a StoredValuesRef as it is and spooled files as their SpooledFilesRef —, the AttemptKey and the actor, and returns its TrialCase; a refusal of add_captured_trial_case propagates as it is and has copied nothing.

## surface


serve_kernel: [ORCHESTRATION] MUST call run_start_sequence with config_path, the process's one command-line argument, and open the MCP entrance — MCP over streamable HTTP at the mcp_listen_address of the returned Installation, one tool per catalogue operation — only after it returned; while serving it reads one HTTP request at a time, takes the presented token from its Authorization header in the Bearer form (None when the header is absent or not in that form), passes the body bytes and that token to answer_request and writes back the bytes it returns.
serve_kernel: [VALIDATION_ERROR] When run_start_sequence raises, which has already written the failing step's name, MUST write the exception's reason to standard error — a kernel module's reason holds no token, credential value or configuration content (translate_failure's note), and an exception no kernel module raised is written by its type alone — never a stack trace, open no entrance and return a non-zero exit code; there is no partial start and no retry. Ending the process releases the store lock; nothing the steps already committed is rolled back, and the next start runs the whole sequence again from those records. Binding the listener at mcp_listen_address is the last start step and fails the same way, the step named open_entrance, when the address cannot be parsed as a host and port or the socket cannot be bound; a listener lost while serving ends the process with a non-zero exit code, without retry.
serve_kernel: [BEHAVIOR] MUST read at most one byte more of a request body than the imported RELEASE_CEILING_SURFACE_REQUEST_BYTES_MAX constant allows, so an oversized request still reaches answer_request and is refused there; when answer_request raises StopRequiredError or any other failure it let propagate because its answer is internal_error, MUST first send that request the internal_error answer built by translate_failure, without detail, and then end the process with a non-zero exit code, so the next start derives every run that has not ended (A03 rule 7, A14 rules 5 and 7).
serve_kernel: [DETERMINISM_OR_ORDERING] Requests are handled strictly one at a time, each to its end, run advancement included, before the next one is read (A18 rule 3).
serve_kernel: [RETURN_SHAPE] Returns the process exit code: non-zero after a failed start, a required stop, or any internal_error that answer_request let propagate — in both of the last two cases the request is first answered internal_error without detail and then the process ends — zero only when serving ends normally.
serve_kernel: [ORCHESTRATION] When the surface module is run as a script, python -m cabinet_kernel.surface <config_path>, which is how the host starts the kernel, it MUST call serve_kernel with that one argument and exit with the status serve_kernel returns (decision 25).
serve_kernel: [DEPENDENCY_BOUNDARY] The entrance is the standard library's http.server.HTTPServer, which serves one request at a time, never a threading or forking server; the surface imports nothing outside the CPython 3.12 standard library except BaseModel from pydantic, the one third-party package, pinned by the release in the imported RELEASE_PYTHON_DEPENDENCIES constant, on which the models and the store repository are emitted and which the surface uses to recognise and serialise models (60_contracts.md decisions 22, 25 and 27).
serve_kernel: [BEHAVIOR] Only a POST to the path equal to the imported MCP_ENDPOINT_PATH constant reaches answer_request; any other method on that path is answered 405, any other path 404, and a request carrying an Origin header 403, each without a body and without calling answer_request; no Mcp-Session-Id header is ever sent, one presented is ignored, and no event stream is opened.
serve_kernel: [FIELD_PROJECTION] An empty result of answer_request is answered 202 without a body; any other result is answered 200 with Content-Type application/json and the result as the body. The internal_error answer sent before the process ends is the JSON-RPC error response of answer_request with code -32603, message internal_error and the RefusalAnswer from translate_failure as data, its id read from the body by the same rule as answer_request.

run_start_sequence: [ORCHESTRATION] MUST call, in exactly this order and each exactly once: load_installation with config_path; check_installed_instances with the loaded Installation; open_store with that Installation's data_directory; probe_sandbox; recover_in_flight_attempts; recover_running_runs (A03 rule 8, A09 rule 1, A14 rule 5, A18).
run_start_sequence: [VALIDATION_ERROR] Every step is required: the first step that raises — InstallationRejectedError, RefusedError from the instance check, a store refusal, SandboxUnavailableError, StopRequiredError or any other exception — stops the sequence there and propagates unchanged to the caller, the same exception with its own reason; before it propagates MUST write the failing step's name — load_installation, check_installed_instances, open_store, probe_sandbox, recover_in_flight_attempts or recover_running_runs — as one line to standard error, so the step is named there and the reason stays the exception's own; no later step runs and nothing is retried or skipped.
run_start_sequence: [RETURN_SHAPE] Returns the Installation that load_installation returned, after every step succeeded.

answer_request: [SECURITY_BOUNDARY] MUST check one request in exactly this order, the first failure deciding: the byte length of request_bytes is within the imported RELEASE_CEILING_SURFACE_REQUEST_BYTES_MAX constant, else invalid_request; authenticate_token with presented_token gives an Actor, else unauthorized with one fixed reason that reveals nothing about any record; for tools/call, the message names a catalogue operation and fits that operation's request model with no unknown field — a field typed X | None fitting when it is absent or JSON null — and every bound below, else invalid_request; the actor may call that operation by the actor table, else not_permitted; only then is the operation's handler called (A16 rule 1). initialize, ping and tools/list name no catalogue operation and are answered after the size and token checks, as the note on methods says.
answer_request: [SECURITY_BOUNDARY] Actor table, the only one: owner only — accept_binding, decide_effect_approval, resolve_unknown_outcome, cancel_run, grant_standing_approval, revoke_standing_approval, read_spooled_file, read_fixture_file; an agent whose AgentToken has may_author true only — issue_contract_version, add_trial_case, submit_implementation; owner or an agent with may_author — capture_failed_execution, roll_back_slot; any agent only — try_implementation, propose_binding, compose_flow_version, prove_flow_version; owner or any agent — activate_flow_version, start_run, resume_run, release_run, get_slot, get_repair_view, get_contract_version, get_implementation, get_binding, get_flow, get_flow_version, get_run, list_records; may_author is read from the current token list entry of the agent named by the Actor, and no request field names or changes the actor (A16 rule 3).
answer_request: [VALIDATION_ERROR] Request bounds, each counted as UTF-8 bytes of the field as received: implementation code within the imported RELEASE_CEILING_IMPLEMENTATION_CODE_BYTES_MAX constant; the json_text of a trial case input or expected output, of a flow constant and of a run input within the imported RELEASE_CEILING_STORED_VALUE_BYTES_MAX constant; the decoded bytes of a trial case file within the imported RELEASE_CEILING_TRIAL_FIXTURE_BYTES_MAX constant; every other string anywhere in the request within the imported RELEASE_CEILING_BOUNDED_TEXT_BYTES_MAX constant; a page_size given below 1 or above the imported RELEASE_CEILING_PAGE_SIZE_MAX constant; base64 text that does not decode; each a failure answered invalid_request (A16 rules 4 and 6).
answer_request: [FIELD_ASSIGNMENT] Before any handler runs, MUST replace every JSON text the request carries — the json_text of each RequestJsonValue and RequestConstant, the value_schema of every Port and RequestConstant, the guard_value of every EdgeGuard — by its canonical form obtained from canonical_bytes; a NonCanonicalValueError there is invalid_request, so modules below receive only canonical JSON (A01 rule 1).
answer_request: [ORCHESTRATION] MUST call the handler of the named operation, whose name is handle_ followed by the operation name — exactly one of handle_accept_binding, handle_activate_flow_version, handle_add_trial_case, handle_cancel_run, handle_capture_failed_execution, handle_compose_flow_version, handle_decide_effect_approval, handle_get_binding, handle_get_contract_version, handle_get_flow, handle_get_flow_version, handle_get_implementation, handle_get_repair_view, handle_get_run, handle_get_slot, handle_grant_standing_approval, handle_issue_contract_version, handle_list_records, handle_propose_binding, handle_prove_flow_version, handle_read_fixture_file, handle_read_spooled_file, handle_release_run, handle_resolve_unknown_outcome, handle_resume_run, handle_revoke_standing_approval, handle_roll_back_slot, handle_start_run, handle_submit_implementation and handle_try_implementation — with the Actor and the validated request, encode its answer as the tool result — values as JSON text, file bytes as base64 — and turn any exception the handler raises into a refusal answer through translate_failure, except any failure translate_failure answers internal_error — StopRequiredError, StoreInternalError or any unexpected exception, whatever the handler — which it lets propagate to serve_kernel unchanged, since a store change may already be written and only the next start derives every run again.
answer_request: [SECURITY_BOUNDARY] Text an agent supplies — purposes, implementation code, names — is data: it is never evaluated, imported, compiled, formatted or interpreted in the kernel process; a JSON text it supplies is data too, parsed only as JSON by canonical_bytes and by the schema check of the module that judges it, never evaluated or executed; no answer and no refusal carries a token, a service credential, a host path or a stack trace, an internal error included (A16 rules 5 and 7).
answer_request: [BEHAVIOR] The body is one JSON-RPC 2.0 message, read only after the size and token checks. A JSON object whose jsonrpc is "2.0" with a string method and an id is a request; one with a method and no id is a notification and one with no method a response: both are answered with empty bytes and change nothing. A request's method decides: initialize answers the result {protocolVersion: the imported MCP_PROTOCOL_VERSION constant, capabilities: {tools: {listChanged: false}}, serverInfo: {name: the imported MCP_SERVER_NAME constant, version: the imported MCP_SERVER_VERSION constant}} whatever version its params ask, and keeps no state; ping answers an empty result object; tools/list answers {tools: [...]} as below, ignoring any cursor; tools/call names the catalogue operation in params.name and carries its request in params.arguments, which then pass the remaining checks of the first note.
answer_request: [FIELD_PROJECTION] tools/list lists one tool per catalogue operation in State 5 catalogue order, each {name: the operation name, inputSchema: the schema of its request model}, derived only by this rule: a model is {"type": "object", "properties": its fields in declared order, "required": its fields not typed X | None, "additionalProperties": false}; str is {"type": "string"}, int {"type": "integer"}, X | None {"anyOf": [the schema of X, {"type": "null"}]}, so the published schema admits the null a request may carry, tuple[X, ...] {"type": "array", "items": the schema of X}, an enumeration {"type": "string", "enum": its members in declared order}, a Literal tag {"const": the tag}, and a discriminated union {"anyOf": the schemas of its variants in declared order}; no description, title or other keyword is added.
answer_request: [FIELD_PROJECTION] MUST write every field of an answer model in the JSON text T, a field whose value is None as null, never omitting it (decision 25).
answer_request: [FIELD_PROJECTION] The id of every response is the body's id member when the body is one JSON object whose id is a string or an integer, and null otherwise; reading it checks nothing and decides nothing.
answer_request: [VALIDATION_ERROR] A refusal decided before the operation is known is a JSON-RPC error response whose error is {code, message: the refusal code, data: the RefusalAnswer as {code, reason}}: a body over the size ceiling is -32600 invalid_request; a token refusal -32600 unauthorized; a body that is not JSON -32700 invalid_request; a body that is not one JSON object — a batch array included — or whose jsonrpc is not "2.0" -32600 invalid_request; a request whose method is none of initialize, ping, tools/list and tools/call -32601 invalid_request; a tools/call whose params is not an object with a string name and an object arguments, or whose name is no catalogue operation, -32602 invalid_request.
answer_request: [RETURN_SHAPE] Returns the bytes of one JSON-RPC 2.0 response as UTF-8 JSON, or empty bytes for a notification or a response. A tools/call that reached its operation returns the result {content: [{type: "text", text: T}], isError: B}: T is the answer of the operation as JSON text and B false, or T is the RefusalAnswer as the JSON object {code, reason} and B true for every refusal decided once the operation is known — fit, bounds, canonical form, permission, or translate_failure of an exception the handler raised; every refusal code is a member of = models.RefusalCode.

authenticate_token: [SECURITY_BOUNDARY] MUST obtain the token list from current_token_list on every call, and answer None when it returns None, when presented_token is None, or when presented_token equals no token of that list; the comparison is constant-time with the hmac compare_digest function against the owner token and against every agent token, all of them compared whatever an earlier comparison found (A16 rules 1 and 2).
authenticate_token: [RETURN_SHAPE] Returns an Actor of kind owner with no agent_name for the owner token, an Actor of kind agent with the agent_name of the matching AgentToken for an agent token, or None; never an Actor of kind kernel.

translate_failure: [FIELD_PROJECTION] MUST map a failure to its code of = models.RefusalCode: UnknownReferenceError to unknown_reference, RefusedError to refused, InvalidRequestError and NonCanonicalValueError to invalid_request; StoreInternalError, StopRequiredError and every other exception to internal_error.
translate_failure: [SECURITY_BOUNDARY] The reason of every code but internal_error is the exception's own message cut to at most the imported RELEASE_CEILING_BOUNDED_TEXT_BYTES_MAX constant bytes at a UTF-8 character boundary; internal_error carries an empty reason, never the exception text, type, path or stack trace (A16 rule 7). A kernel module's exception message names records by identity and checks by name and never holds a token, a credential value, configuration content or a stored value, so the cut message reveals nothing those rules keep back.

show_port_refs: [FIELD_PROJECTION] For each PortRef, in order, MUST produce one ShownPort with the same port name and one ShownItem per referenced item in order: a StoredValuesRef reads its StoredValue records with read_records using RecordsById, and a value carriage item becomes ShownContent with its value_id, its canonical JSON text read with read_value_bytes from a StoredValueSource and its class, a file carriage item becomes ShownFile with digest, size, media type, class, its value_id and no spooled_file; a file carriage StoredValue always has a media type, its fixture taking its port's one media type (decision 18), so one whose media_type is None is a record that cannot be read and raises StoreInternalError, propagating as the validation note says; a SpooledFilesRef reads its SpooledFile records with SpooledFilesByKey and each becomes ShownFile carrying its full SpooledFileKey and no value_id; a FileFactsRef becomes one ShownFile per FileFacts with the class the FileFactsRef carries, no spooled_file and no value_id.

show_port_refs: [RETURN_SHAPE] Returns the tuple of ShownPort, one per given PortRef, in the given order.

handle_get_repair_view: [VALIDATION_ERROR] An unknown slot_id is unknown_reference; the page size is the imported RELEASE_CEILING_PAGE_SIZE_DEFAULT constant when absent; a given continuation token that is not base64url text without padding of the canonical JSON this handler issues, or that names another slot_id, is invalid_request; a store token it carries that names no record of that type is refused by page_records as invalid_request (A16 rule 6).
handle_get_repair_view: [DETERMINISM_OR_ORDERING] The continuation token this handler issues is base64url without padding of the canonical JSON of the slot_id, the implementation set used for the first page and the store token of the last item; passed back, the next page uses that saved implementation set, not the current one, and every other part of the view is read again as of the new request; the token is None when page_records returns none.
handle_get_repair_view: [SECURITY_BOUNDARY] The current implementation is the only place where an agent receives implementation code: it is shown with code to owner and agent alike; corpus cases, trial executions and NodeExecutions are masked under the surface masking rule, each NodeExecution's failure_detail by the class of its execution (K-12, A07).

handle_list_records: [ORCHESTRATION] MUST call page_records with the record_type, the filter — an in_set filter in canonical form, its values without duplicates and in code-point order, so that equal sets page alike and the continuation token binds to that form —, the page size — the imported RELEASE_CEILING_PAGE_SIZE_DEFAULT constant when absent — and the continuation token; for the record type run, each listed Run is answered with read_run and shown as handle_start_run shows one; every other record is shown under the surface masking rule, implementations without code for an agent and with code for the owner, NodeExecutions and TrialExecutions with their failure_detail masked by the class of their execution.
handle_list_records: [BEHAVIOR] A filter value naming no record, or a set filter some of whose members name none, is not a refusal: the page holds what the existing members match, possibly nothing; a page_records refusal of a token issued for another type or filter is passed on as invalid_request.
