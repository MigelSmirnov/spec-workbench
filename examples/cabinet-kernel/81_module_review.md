The review also asked the Factory directly what its generator would receive. It ran `normalize_spec`,

- **Dropped collaborators.** The Factory's own hygiene judge derives `imports.module_internal` and

  - `effects` lacked `clock.kernel_now`;
  - `runs` named no `store.record_change` at all;
  - `sandbox` lacked `RELEASE_CEILING_FAILURE_DETAIL_BYTES_MAX`.

Both defects are repaired in State 7. After the repair, every behavioral module passes the
underspec gate, and every symbol a note names is in that module's Factory imports.

## Questions to the owner (answered above)

### Q1 — `functions.roll_back_slot`: the serving implementation without a current verdict

- **Address.** A04 rule 5 (`02_rules_functions.md`). The repair would then be one ordering
  sentence in the `roll_back_slot` notes.
- **Quotes.**
  - A04 rule 5: "Rollback activates an earlier implementation … that already holds an `admitted`
    verdict over the current corpus … Naming the implementation that is already current returns
    the current activation and records nothing. An implementation without such a verdict is
    refused".
  - A04 rule 7: after a capture, the serving implementation "visibly lacks a verdict over the
    current corpus … and serves until another implementation is activated".
- **Case.** A failed execution is captured, so the corpus grows. The owner then calls
  `roll_back_slot(slot, serving_implementation)`.
  - **A:** the verdict check comes first, so the result is `refused`.
  - **B:** the already-current rule comes first, so the current Activation is returned and nothing
    is recorded.
- **Material difference.** The refusal code versus a successful answer. Witness
  `kernel_a04_rollback_requires_current_verdict` covers only a non-current implementation.

### Q2 — `runs.recover_running_runs`: store order across three statuses

- **Address.** State 6 (`60_contracts.md` relations of `store.read_records`, or the `Run` model).
  State 2 A14 rule 5 already decides the meaning.
- **Quotes.**
  - A14 rule 5 (`02_rules_runs.md`): "derives every run that has not ended — `running`,
    `awaiting_approval` or `pending` — again from its records, oldest first in store order".
  - A19 rule 3: "The kernel orders its records only by the store's order".
- **What the slice gives.**
  - `RunsByStatus` answers one status at a time.
  - `Run` has no `store_position`.
  - `RecordSet` carries no positions.

  So `runs` cannot merge the three answers into store order.
- **Case.** An older `pending` run whose resolved attempt lets it advance, and a newer `running`
  run.
  - **A:** the older run is advanced first. Its sends and NodeExecutions get the earlier positions.
  - **B:** status-by-status concatenation (or ordering by `started_at`, which A19 rule 3 forbids)
    advances the newer one first.
- **Material difference.** The order of sends seen by services, and the trace order.
- **Possible decision.** Either a relation that answers every not-ended run in store order, or the
  store position on the answer.

### Q3 — `surface`: an agent listing `effect_attempt` sees unmasked `personal_data` refs

- **Address.** State 6 (`60_model_closure_operations.json`, `ShownRecords.effect_attempts`).
- **Quotes.**
  - A07 rule 4 (`02_rules_flows.md`): "An agent never receives a `personal_data` value: wherever the
    surface would return one to an agent — … trace records — it returns only the value's digest and
    class (K-14), and no `value_id`. The same holds for a `personal_data` file: an agent gets its
    digest and class, and not its size, media type or spool facts."
  - State 5: `list_records` is open to "owner, agent".
- **What the slice gives.**
  - `ShownRecords.effect_attempts` is typed `tuple[EffectAttempt, ...]`.
  - `EffectAttempt.inputs` is `tuple[PortRef, ...]`. These are `StoredValuesRef` (`value_id`),
    `SpooledFilesRef` (spool keys) and `FileFactsRef` (size, media type), added by State 6
    decision 12.
  - No `ShownPort` slot exists, so `show_port_refs` cannot be applied.
- **Behaviors.**
  - **A:** what the type forces. The agent receives the `value_id` or the file facts.
  - **B:** what A07 requires. Digest and class only.
- **Material difference.** A disclosure boundary.
- **Possible decision.** A shown attempt (for example `ShownEffectAttempt` with
  `inputs: tuple[ShownPort, ...]`). The `handle_list_records` note would then pass the inputs
  through `show_port_refs`.

## Remarks, not blocking

- **Published `inputSchema` and null.** By decision 22's closed rule, the published `inputSchema`
  maps `X | None` to the schema of X, so it does not admit `null`. The kernel accepts `null` after
  N13. An MCP client that validates against the published schema would therefore omit those fields
  rather than send `null`. Making the rule `anyOf [X, null]` would be a State 6 change and is left
  to the owner.
- **Stub `base_url` in the A09 witness.** `kernel_a09_no_redirect_plain_http_restricted` passes
  only if the fixture's stub `base_url` is a loopback IP literal: the service_invoker notes accept
  "a loopback IP address literal", not `localhost`. `RUNTIME_SURFACE.md` could say so. That is a
  test-file change, and it is not made here.

## Tool defects (reported, `tools/` untouched)

1. **Underspec refusal not gated.** `design_notes --propagate` counts `factory_coverage` blocks
   (29 at `aa8b93d`), but neither the State 7 notes gate, `design_assembly` nor admission refuses on
   them. The Factory's `generate_agent` refuses each such callable.
2. **Collaborator names dropped from imports.**
   - The State 7 gate checks undeclared collaborators only as `name(`
     (`tools/notes_workbench/language.py`).
   - The skeleton derives `module_internal` with the Factory hygiene judge, which drops clauses
     that contain negative markers.
   - Together, these let a collaborator or constant that a note names go unimported without a
     finding.
3. **Review packet omits union variants.** `module_review_workbench` `referenced_models` follows
   `fields` but not `variants`, so review packets leave out the variants of discriminated unions
   (`StoreChange`, `RecordQuery`, `RecordFilter`, `PortRef`, …). The Factory's own slicer does
   include them. This affects only what reviewers see.
