# Stage 8.1 re-review — port ownership moves to the models module

## Why this review exists

`models` was being generated by the LLM instead of the deterministic emitter,
and the drift that follows from that broke a Factory run: one generation
produced `durable_acceptance: "DurableAcceptanceVerification" | None`, which is
valid syntax and an unimportable module.

The cause was ownership. The Factory selects deterministic models emission only
when every runtime name in the `models` section is owned by the `models` module:

```python
model_names = _runtime_model_names(spec)      # includes kind: interface
if model_names and model_names <= owned:      # owned = module_functions["models"]
    return "models"
```

This case declared 79 runtime names and gave the `models` module 70. The nine
missing ones were the ports, each assigned to the module that implements it. The
subset test failed and the Factory silently fell back to the LLM.

No rule was broken, because the rule was not written down. SPEC_STANDARD said
nothing about which module owns a `kind: interface`, and the authoring index
instructed the author to add "физический export owner" without constraining it.
Assigning `AccessControlBackend` to `access_control` was the natural reading.
Both documents have now been corrected; this review records the matching change
to the case.

## Change

For each of the nine ports:

- `module_functions[implementation]` loses it, `module_functions["models"]` gains it;
- `imports.internal[implementation]` loses it, `imports.internal["models"]` gains it;
- `imports.module_internal[implementation]["models"]` gains it, so the module
  that satisfies the port imports it from the owner;
- the one existing consumer edge, `api <- access_control: AccessControlBackend`,
  now reads `api <- models: AccessControlBackend`.

Ports moved: `AccessControlBackend`, `ArchiveUnitOfWork`, `SourceByteStore`,
`RegistryContextRepository`, `SynchronizationRepository`,
`VpsSynchronizationTransport`, `PlanActualRepository`,
`HoldedPublicationRepository`, `RetentionReleaseRepository`.

No contract signature changed. No implementation moved. `function_order` is
untouched: none of the ports appears in it.

## Adversarial review

**Does the models module now own behaviour?** No. A port is a declared boundary
with no body. Every class that satisfies one stays where it was —
`PostgresArchiveUnitOfWork` in `archive_runtime`, `PostgresAccessControlBackend`
in `access_control`. The "must not own" list of `domain_models` is intact: no
persistence, transport lowering, or authorization policy moved with the
declaration.

**Does this contradict State 3?** It did, and the document is corrected rather
than bypassed. `domain_models` previously declared "Exports model types only"
and "Knows field structure ... only", which excludes method signatures. Its
`Knows` and `Public surface` sections now state that it also owns port
declarations, and say why the lowering does not follow them.

**Do the implementations still see their ports?** Yes, and now explicitly: each
implementing module declares `imports.module_internal[module]["models"]` with
its own port, which is how `client_portal_sandbox` has always expressed the same
relation (`budget_repository <- models: BudgetRepository`).

**Do consumers now depend on adapters?** Less than before. `api` previously
reached `AccessControlBackend` through `access_control`, so depending on the
port meant depending on the module that also holds the concrete Postgres
adapter. It now depends on `models`.

**Are the port method contracts still resolvable?** Yes. They are `Port.method`
keys in `contracts` and were not touched; all nine ports keep between 2 and 16
method contracts, satisfying the standard's rule that an exported interface has
at least one.

**Is the deterministic emitter actually selected now?** Yes:
`deterministic_emission_kind(spec, "models") == "models"`, with 79 of 79 runtime
names owned. This also clears the nine `ownership_conflict` findings the
deployed-tree inventory reported against the previous arrangement, and lets
`model_surface_gate` check that each declared interface is materialized as a
Protocol class.
