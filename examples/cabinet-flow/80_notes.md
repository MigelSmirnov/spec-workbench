# State 7 — Cabinet Flow generation notes

## Access Control
authorize_action: [BEHAVIOR] MUST classify the closed catalogue action as owner-only, authoring, inspect/run or disclosure-bearing and return authority for this request with the actor's effective disclosure ceiling. An agent with `may_author = false` may inspect, run and read traces; `may_author = true` additionally permits the enumerated authoring, trial-request and implementation-activation actions. No delegation can authorize owner decisions, and the check MUST append no action record, perform no requested operation and reveal nothing about whether its target exists.
issue_delegation: [BEHAVIOR] MUST require the sole active owner, an installation-known credential binding whose channel matches the requested channel, a closed disclosure ceiling and a bounded agent label. In one unit of work it mints a fresh delegation identity, samples `module:system_clock.now` for `issued_at` and appends exactly one active delegation; equal fields never reuse another delegation because later actions remain attributable to the exact permission. Every refusal leaves the owner, credentials and existing delegations unchanged and returns no credential material.
resolve_actor: [BEHAVIOR] MUST authenticate exactly one owner or active delegation for the supplied channel before inspecting any resource named by the request. Failed authentication atomically advances only the matching persisted credential/channel throttle: failures 5 through 9 delay for 1, 2, 4, 8 and 16 seconds, and failure 10 blocks for 900 seconds; attempts during a block neither increment nor extend it, and agent failures cannot throttle owner access. A successful authentication after the block expires resets that throttle record. Missing, invalid, ambiguous, revoked, blocked and cross-channel credentials have one indistinguishable refusal, and credential material is never persisted, returned or logged.
revoke_delegation: [BEHAVIOR] MUST let only the sole active owner compare-and-set the named delegation from active to permanently revoked, sampling `module:system_clock.now` once for the immutable revocation time and recording the bounded owner reason. Exact replay returns the recorded revocation without changing its time or reason; a conflicting replay, stale state or owner mismatch changes nothing. Revocation takes effect on the next authentication and MUST NOT rewrite historical ActorRefs, cancel runs, revoke installation credentials or expose credential material.

## Admission
current_admission: [BEHAVIOR] MUST read the latest immutable AdmissionVerdict for the exact contract-version and implementation pair and return its corpus-snapshot identity, runtime revision, ordered TrialExecution references and complete refusal reasons, or explicit absence. It MUST distinguish an earlier admitted verdict from admission over the presently active corpus: corpus growth never rewrites old evidence and a verdict for another pair is never substituted. The lookup performs no trial, activation or state change, and missing, mismatched or unreadable evidence is never interpreted as admitted.
run_trial: [BEHAVIOR] MUST resolve the exact immutable contract, implementation, pinned runtime and complete active-corpus snapshot, then execute every active case in deterministic order in a fresh disposable sandbox. Each attempted case appends one immutable TrialExecution; expected outputs are compared by digest after strict input/output validation, and only a non-empty corpus with one conforming execution for every case yields `admitted`. Empty corpus, absent execution and non-conformance produce `empty_corpus`, `missing_trial_execution` and `non_conforming_trial` reasons respectively, with all applicable reasons retained. After the complete run it samples `module:system_clock.now` and appends exactly one kernel-authored AdmissionVerdict; infrastructure failure cannot fabricate a verdict, and the operation never changes corpus membership, contracts, implementation bytes, authority or slot activation.
