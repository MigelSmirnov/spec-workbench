# State 7 — Cabinet Flow generation notes

## Access Control
authorize_action: [BEHAVIOR] MUST classify the closed catalogue action as owner-only, authoring, read-and-run or disclosure-bearing and return authority for this request with the actor's effective disclosure ceiling. An agent with `may_author = false` may view records, run flows and read traces; `may_author = true` additionally permits the enumerated authoring, trial-request and implementation-activation actions. No delegation can authorize owner decisions, and the check MUST append no action record, perform no requested operation and reveal nothing about whether its target exists.
issue_delegation: [BEHAVIOR] MUST require the sole active owner, an installation-known credential binding whose channel matches the requested channel, a closed disclosure ceiling and a bounded agent label. In one unit of work it mints a fresh delegation identity, samples `module:system_clock.now` for `issued_at` and appends exactly one active delegation; equal fields never reuse another delegation because later actions remain attributable to the exact permission. Every refusal leaves the owner, credentials and existing delegations unchanged and returns no credential material.
resolve_actor: [BEHAVIOR] MUST authenticate exactly one owner or active delegation for the supplied channel before inspecting any resource named by the request. Failed authentication atomically advances only the matching persisted credential/channel throttle: failures 5 through 9 delay for 1, 2, 4, 8 and 16 seconds, and failure 10 blocks for 900 seconds; attempts during a block neither increment nor extend it, and agent failures cannot throttle owner access. A successful authentication after the block expires resets that throttle record. Missing, invalid, ambiguous, revoked, blocked and cross-channel credentials have one indistinguishable refusal, and credential material is never persisted, returned or logged.
revoke_delegation: [BEHAVIOR] MUST let only the sole active owner compare-and-set the named delegation from active to permanently revoked, sampling `module:system_clock.now` once for the immutable revocation time and recording the bounded owner reason. Exact replay returns the recorded revocation without changing its time or reason; a conflicting replay, stale state or owner mismatch changes nothing. Revocation takes effect on the next authentication and MUST NOT rewrite historical ActorRefs, cancel runs, revoke installation credentials or expose credential material. The bounded owner reason MUST be stored as `revocation_reason` together with `revoked_at`.

## Admission
current_admission: [BEHAVIOR] MUST read the latest immutable AdmissionVerdict for the exact contract-version and implementation pair and return its corpus-snapshot identity, runtime revision, ordered TrialExecution references and complete refusal reasons, or explicit absence. It MUST distinguish an earlier admitted verdict from admission over the presently active corpus: corpus growth never rewrites old evidence and a verdict for another pair is never substituted. The lookup performs no trial, activation or state change, and missing, mismatched or unreadable evidence is never interpreted as admitted.
run_trial: [BEHAVIOR] MUST resolve the exact immutable contract, implementation, pinned runtime and complete active-corpus snapshot, then execute every active case in deterministic order in a fresh disposable sandbox. Each attempted case appends one immutable TrialExecution; expected outputs are compared by digest after strict input/output validation, and only a non-empty corpus with one conforming execution for every case yields `admitted`. Empty corpus, absent execution and non-conformance produce `empty_corpus`, `missing_trial_execution` and `non_conforming_trial` reasons respectively, with all applicable reasons retained. After the complete run it samples `module:system_clock.now` and appends exactly one kernel-authored AdmissionVerdict; infrastructure failure cannot fabricate a verdict, and the operation never changes corpus membership, contracts, implementation bytes, authority or slot activation. It MUST read the contract only with `module:slot_registry.contract_version`, the implementation record only with `module:slot_registry.implementation_record` and the corpus snapshot only with `module:trial_corpus.active_corpus`, and execute each case only with `module:sandbox_supervisor.execute_function`; it never reconstructs a contract, a corpus or an execution result from its arguments. The pinned runtime MUST be the contract's `runtime_revision_ref` and the corpus identity the snapshot's `corpus_digest`; the verdict records `contract_version_ref`, `runtime_revision_ref` and `corpus_digest`.

## Bootstrap
start_kernel: [BEHAVIOR] MUST compose one fail-closed start from the host-selected installation and protected configuration references, inject `module:system_clock` before any timestamped work, and reject missing credentials, incompatible releases or schemas, and mixed production/rig targets. It MUST open the durable store, idempotently seed only missing vocabulary in an explicit unit of work, sweep every accepted binding against the pinned manifest, require confirmed sandbox health, and reconstruct every non-terminal Run from durable evidence in that order. MCP and HTTP listeners open only after all checks and recovery succeed; any store, manifest, sweep, supervisor, recovery or listener failure returns a typed bounded refusal, closes anything already opened, and leaves no gateway serving. Success reports the manifest revision and readiness of every required component without credentials or host paths; startup may append only seed, binding-drift and recovery records and never creates business facts. The closed flow plan requires this coordinator path to reach the exact operations `advance_run`, `begin_unit_of_work`, `cancel_run`, `commit_unit_of_work`, `manifest_revision`, `now`, `reconcile_outcome`, `release_ceilings`, `resolve_service_target`, `resume_runs`, `seed_vocabulary`, `serve_http`, `serve_mcp`, `supervisor_health`, `sweep_manifest_drift`.

## Flow Proof
prove_flow: [BEHAVIOR] MUST read the exact immutable FlowVersion only with `module:flow_registry.flow_version`; for every function node it reads the pinned contract only with `module:slot_registry.contract_version`, for every operation node the pinned binding only with `module:operation_bindings.binding_version`, and for semantic evidence only with `module:semantic_vocabulary.term_revision` and `module:semantic_vocabulary.find_relation`. It MUST NOT decode a graph, contract, binding or vocabulary record from a string, mapping or caller-supplied substitute. It judges the complete declared nodes and edges for pin validity, schema and semantic evidence without coercion, required conversion/resolution nodes, carriage and media, cardinality and mapping, disclosure propagation and ceilings, exactly-once required inputs, acyclicity, pure-node reachability, closed guards and required outputs outside guards. It returns every finding in stable graph order, including unavailable evidence as refusal rather than warning-only success, derives each function output disclosure plus the highest operation effect class, uses the caller-supplied `decided_at` without reading any clock, and persists the result only with `module:flow_registry.record_flow_proof`. For the same flow and vocabulary basis it returns the equivalent immutable proof; it never activates the flow, invokes a node or mutates dependencies, and later binding suspension does not rewrite the proof.

binding_version: [BEHAVIOR] MUST return the one immutable OperationBindingVersion named by the exact reference, including a suspended historical version, and MUST refuse an unknown or ambiguous reference without substituting a current version or consulting a changing manifest projection. It performs no acceptance, retirement, invocation or persistence mutation.

flow_version: [BEHAVIOR] MUST return the one immutable FlowVersion named by the exact content identity and MUST refuse an unknown or ambiguous reference without substituting a current version, composing partial graph state or changing any Flow record.

record_flow_proof: [BEHAVIOR] MUST open one `module:operational_store.begin_unit_of_work`, append the complete immutable FlowProof, and finish only with `module:operational_store.commit_unit_of_work`; any validation, conflict or commit failure uses `module:operational_store.rollback_unit_of_work` and leaves no partial record. An exact replay returns the stored equivalent, while the same proof identity with different content is refused; it reads no clock and changes no flow version, activation, binding or vocabulary record.

## Flow Registry
activate_flow_version: [BEHAVIOR] MUST compare-and-set the current selection and append one immutable FlowActivation only when the exact version belongs to the active Flow and has a matching `proven` FlowProof. It derives the highest effect from pinned accepted bindings: the kernel alone may put a `read` flow into service, while every higher class requires the active owner and a complete kernel-generated statement naming every non-read node; agent prose grants nothing. Missing or mismatched proof, retirement, suspended owner, stale expected activation or concurrent selection changes no state. Selecting an earlier version appends new history, and no activation, approval or grant is inherited; the operation invokes no node or service. For an effectful version it MUST regenerate the statement only with `module:owner_authority.owner_statement` and require the supplied owner statement to equal the generated text exactly. `activated_at` MUST be one sample of `module:system_clock.now`; no caller supplies or alters it.
composition_view: [BEHAVIOR] MUST authorize the actor and return a bounded, deterministic page of composable accepted contract and operation-binding versions, semantic ports, effect classes and the accepted vocabulary evidence needed to connect them, filtered by the actor's disclosure ceiling. Retired or suspended facts are labelled rather than replaced, and implementation bodies, credentials and storage paths are absent. Invalid filters or cursors, unavailable required evidence and requests that would make a partial view look complete return typed refusal without changing state.
create_flow: [BEHAVIOR] MUST authorize authoring, validate bounded name and purpose strictly as data, mint the stable Flow identity in the kernel, and atomically append one active Flow container without a graph, version or activation. Caller identity, initial graph, approval and grant fields are refused. An explicitly idempotent replay returns the exact existing record; a conflicting duplicate, invalid text or persistence failure leaves no partial lifecycle record and never touches services. `created_at` MUST be one sample of `module:system_clock.now`; no caller supplies or alters it.
current_flow_activation: [BEHAVIOR] MUST resolve one exact Flow and return the latest successful immutable activation in its compare-and-set chain together with that activation's exact version, or explicit absence when none exists. It MUST expose retirement and reject an unknown Flow, unavailable record or corrupt chain; it never guesses a fallback, treats an unproven version as current, or inherits a selection from another Flow or older similarly named version. The lookup has no state or service effect.
derive_highest_effect_class: [BEHAVIOR] MUST examine every exact pinned accepted OperationBindingVersion and return the maximum value in the closed effect-class ordering, with `read` for a set containing no higher effect. Unknown, duplicate-conflicting, unaccepted or unavailable bindings are refused rather than ignored or downgraded, and caller declarations cannot override the result. The derivation is deterministic and performs no mutation, authorization or service invocation.
register_flow_version: [BEHAVIOR] MUST authorize authoring, require an active exact Flow, and accept one complete bounded graph whose inputs, outputs, function and operation nodes, edges, constants, guards and mappings pin exact versions and contain no code or expressions. After `validate_flow_registration`, it obtains the content identity from `module:identity` and atomically appends the immutable FlowVersion, returning the existing equal version for identical content. Caller-selected identity, partial/inherited graph state, malformed variants and conflicting content are refused without persistence. Registration creates no proof, activation, approval or grant and does not make the version runnable. `authored_at` MUST be one sample of `module:system_clock.now`; no caller supplies or alters it.
retire_flow: [BEHAVIOR] MUST authorize the actor and compare-and-set the exact active Flow and expected current activation to final `retired`, sampling `module:system_clock.now` only on the successful transition and preserving the bounded reason, actor and time. An exact replay returns the first result; unknown Flow, stale state or activation, conflicting repeat and transactional failure change nothing. Retirement blocks new versions, activations and Runs but never deletes or rewrites versions, proofs, activation history, existing Runs, traces, approvals or grants, and invokes no service. It MUST write the retiring actor to `retired_by`, the sampled time to `retired_at` and the bounded reason to `retirement_reason`, each exactly once.
validate_flow_registration: [BEHAVIOR] MUST validate one complete bounded self-contained graph before identity or persistence: every declared collection and variant is well formed, identifiers and references are exact and unique where required, all local endpoints exist, and no graph, activation, approval or grant field is inherited or caller-generated outside the accepted shape. It refuses caller-supplied version identity, embedded code or expressions, unbounded payloads, missing structural parts and references to another Flow. This pure structural check neither proves semantic compatibility nor mutates state; whole-graph semantic findings remain the responsibility of `module:flow_proof`.

## Http Gateway
serve_http: [BEHAVIOR] MUST construct the loopback FastAPI application only after startup supplies the explicit `module:kernel_surface` and `module:access_control` dependencies. Its emitted fixed routes accept the six closed kernel-surface operations, reject unknown routes, unsupported media types, malformed bodies, unknown fields and bodies above the injected `surface_request_bytes_max` before delegation, extract the listener-established credential handle, delegate exactly once, and map the bounded typed result to HTTP. Authentication, policy, retry and domain effects remain with their owning modules; public refusals are stable and reveal no record existence, credential, stack trace or host path. The closed flow plan requires this coordinator path to reach the exact operations `activate`, `author`, `authorize_action`, `inspect`, `now`, `owner_decide`, `request_trial`, `resolve_actor`, `resolve_credential`, `run_flow`.

## Identity
canonicalize_fields: [BEHAVIOR] MUST serialize the already selected complete defining fields for a known record kind under an explicit supported canonicalization version, with type and length boundaries, fixed field and collection ordering, and unambiguous numeric, text, byte, optional and variant forms. Missing, duplicate, out-of-domain or non-canonicalizable fields and unknown versions are refused rather than normalized from ambient language or storage defaults. Provenance, lifecycle, timestamps and storage facts are included only when the record-kind definition declares them defining; the operation is deterministic and state-free.
digest_canonical_bytes: [BEHAVIOR] MUST compute one deterministic content digest from the exact canonical byte sequence using the identity algorithm fixed by the kernel release and return it in the release-defined encoding. It neither reparses nor rewrites bytes, accepts no caller-selected algorithm or claimed digest, and refuses input beyond the release ceiling. Equal bytes produce equal digests and any byte difference participates; the operation has no state, entropy or storage effect.
digest_value: [BEHAVIOR] MUST bind the exact declared schema identity and optional semantic-term revision to the schema-aware canonical bytes of a previously validated value, then return one deterministic content digest. Cross-schema equality, unvalidated or mismatched values, unsupported families, non-canonical number/text forms and content above the digest ceiling are refused. Retention, disclosure, producer, time and storage location do not perturb the digest, and the operation stores nothing.
identify_binding_version: [BEHAVIOR] MUST canonicalize the exact manifest operation identity and digest, ordered typed input/output ports, effect class, replay behavior, idempotency-key ports, preconditions, preview ports and outcome-read binding reference, then digest all behavior-affecting facts into one binding-version identity. Missing manifest pins, ambiguous or duplicate ports, unsupported variants, non-canonical fields and caller-supplied identity are refused. Author, acceptance time, rationale and lifecycle are excluded; equal defining content yields one identity without proposing, accepting or persisting a binding.
identify_contract_version: [BEHAVIOR] MUST canonicalize the exact Slot reference, ordered typed input/output ports, clamped resource bounds and sandbox-runtime revision, with every defining contract field present, then return the content digest plus canonicalization-version identifier. Caller identity, authoring actor, issue time, rationale and storage facts are forbidden inputs; missing fields, ambiguous ordering, unsupported canonicalization and out-of-domain values are refused. Equal defining content yields one identity, and issuing or persisting the contract remains with `module:slot_registry`.
identify_flow_version: [BEHAVIOR] MUST canonicalize one exact Flow reference and the complete graph—declared inputs and outputs, graph-local identities, pinned nodes, semantic ports, based edges, constants, guards and mappings—using canonical graph ordering independent of request order. Every behavior-changing fact changes identity, while authoring actor, registration time, rationale, proof, activation, approval and grant do not participate. Duplicate local identity, incomplete variants, non-canonical constants, unsupported versions and caller-supplied identity are refused; the operation neither registers nor proves the flow.
identify_implementation: [BEHAVIOR] MUST digest the canonical tuple of exact contract-version reference, bounded entry-point name and byte-exact implementation content, without importing or executing the code. A different contract, entry point or byte changes identity; identical defining content yields the same identity across filenames, actors and submission times. Missing or oversized bytes, invalid entry point and any claimed identity are refused, and storage and Slot association remain with `module:slot_registry`.
identify_trial_case: [BEHAVIOR] MUST canonicalize the exact contract-version reference, the input and expected-output tuples in their supplied order, protected classification and resolved fixture digests, then digest all defining test evidence into one trial-case identity. The caller supplies both tuples in the corresponding contract-port order after `module:trial_corpus` has validated that correspondence; this function reads only the declared `StoredValue` fields and does not infer a port identifier from a stored value. Missing evidence, unresolved fixtures, non-canonical values and caller identity are refused; any defining evidence change changes the identity. Author, capture time and rationale are excluded, and corpus registration and lifecycle remain with `module:trial_corpus`.
mint_identity: [BEHAVIOR] MUST accept only a closed continuing-entity kind and installation namespace, consume protected collision-resistant entropy/counter state, and return a new opaque identity separated from every other entity-kind namespace. Caller candidates, semantic labels, timestamps and caller-controlled entropy are forbidden; unknown kinds, unavailable safe entropy and detected collision fail without a time- or label-based fallback. Only generator bookkeeping may change: minting neither creates the entity nor reserves business meaning, and its persistence remains with the owning module.

## Installation
manifest_revision: [BEHAVIOR] MUST read the operator-established protected installation configuration and return the one immutable repository revision plus opaque manifest-root reference pinned for the running kernel. No request, flow or stored domain record can nominate a revision, moving branch or `latest`; missing, malformed, unavailable or unverifiable pins refuse startup and manifest access. The result exposes neither host filesystem path nor credential, changes no state, and every manifest projection and run service fact must resolve from this same revision.
release_ceilings: [BEHAVIOR] MUST return the complete immutable `ReleaseCeilings` shipped with the exact running kernel release, containing the release-fixed limits represented by that closed model and no undeclared release metadata. Every declared ceiling must be positive and internally consistent; a missing or malformed record refuses startup with no unbounded fallback. Runtime and dependency revision compatibility is validated by the release and manifest owners and MUST NOT be encoded as extra `ReleaseCeilings` fields. This operation accepts no selector or host/per-flow override, returns the same whole record to every consumer, and changes no state.
resolve_credential: [BEHAVIOR] MUST resolve at the moment of use one protected credential-binding reference for the exact expected purpose, channel or service instance, and authorized closed caller-component kind, returning only a short-lived component-local non-serializable handle. It MUST obtain the current instant only from `module:system_clock.now` when checking expiry; direct host-clock reads and caller-supplied time are forbidden. Unknown, expired or malformed references, purpose/target mismatch, unauthorized components and unavailable protected storage yield a uniform typed refusal without secret or host-location detail. Raw values, arbitrary secret names and paths are never inputs; credential material is never logged, traced, previewed, persisted, placed in process arguments or injected into a function environment, and protected-provider lookup writes no kernel record.
resolve_service_target: [BEHAVIOR] MUST resolve an exact service identity through the host-selected installation configuration and pinned manifest revision to the single configured instance, returning only its immutable instance identity, environment class, declared channel and non-secret routing facts with a separate credential reference. Caller, flow, redirect and request data cannot supply or replace instance ID, address, headers, channel or class. Unknown services, absent or off-manifest instances, unsupported channels, invalid configuration and any mixture of production with non-production targets refuse startup or Run creation before execution; resolution changes no installation state, while a caller may pin the returned target in a new Run.

owner_decide: [BEHAVIOR] MUST accept only the active owner and one closed decision variant with its exact target revision or status, expected compare-and-set state and kernel-generated statement where required, then atomically route it to the single owning module. ## Operation Bindings
accept_binding_version: [BEHAVIOR] MUST let only the active owner compare-and-set one exact proposed binding version to accepted after re-reading the same manifest operation, proving its digest and invocation facts still match, and validating all semantic ports and effectful preview/outcome-read safety fields. The complete kernel-generated statement must name service, operation, purpose, effect class, accepted disclosure classes and preview ports; altered or agent-substituted prose grants nothing. Non-owner or suspended owner, stale status/version, drift, incomplete safety evidence or concurrent decision changes nothing. Success appends one immutable acceptance for that version only, samples its time from `module:system_clock`, and creates no invocation, flow activation, approval or grant. It MUST regenerate the statement only with `module:owner_authority.owner_statement` and require the supplied owner statement to equal the generated text exactly. It MUST write the owner to `accepted_by` and one sample of `module:system_clock.now` to `accepted_at`, each exactly once.
binding_for_invocation: [BEHAVIOR] MUST resolve exactly the binding and version pinned by the FlowVersion, require accepted and non-retired status, and perform a current exact manifest drift check before returning its ports, manifest facts, preview/outcome-read references and digest. It never upgrades to latest, falls back, substitutes a reissued version or trusts cached success. Unknown or mismatched versions, proposed/retired/suspended status, absent or materially changed operation and unavailable manifest evidence return a non-invocable reason and call no service; only deterministic drift-owned suspension or equivalent-facts reissue evidence may be appended. A version whose `accepted_at` is absent MUST be refused as not accepted.
propose_binding: [BEHAVIOR] MUST authorize authoring, resolve the exact manifest operation and digest, validate every typed port against accepted semantic/schema evidence, and copy channel, effect class, replay and idempotency facts verbatim rather than accepting them from the caller. Every non-read proposal must name valid preview ports and an accepted same-service `read` binding for outcome reconciliation. Missing/stale operations, manifest contradictions, invalid or duplicate ports, unsafe effectful shape, wrong reconciliation binding and caller identity are refused without a record. Otherwise `module:identity` computes the immutable version identity and one proposed version is appended; it remains non-invocable until exact owner acceptance. It MUST copy manifest-owned facts only from `module:manifest_reader.manifest_operation` and validate every semantic port only with `module:semantic_vocabulary.term_revision`. The proposed version MUST leave `accepted_by` and `accepted_at` absent; it never invents an acceptance time or actor. `preconditions` MUST be copied from the manifest record together with effect class, replay and the idempotency key.
retire_binding: [BEHAVIOR] MUST authorize the actor and compare-and-set the exact binding, expected current lifecycle status and version to final retired, sampling `module:system_clock.now` only on success and preserving the bounded actor/reason evidence. An exact replay returns the first retirement; unknown binding, stale expectation, conflicting repeat or transaction failure changes nothing. Retirement blocks new flow references and invocation but never deletes or substitutes manifest records, immutable binding versions, FlowVersions, proofs, Runs, approvals or traces, and calls no service.
sweep_manifest_drift: [BEHAVIOR] MUST deterministically reconcile either every accepted binding or one exact binding/version against the configured manifest revision using the fixed material set: channel, effect class, replay behavior, idempotency-key declaration and preconditions. ## Operation Invoker

## Operational Store
begin_unit_of_work: [BEHAVIOR] MUST accept only a closed purpose discriminator and a bounded correlation identity, open one new `sqlite3` connection to the operational-store database established at startup, start one immediate write transaction on it, and return one `OperationalUnitOfWork` — a `SqliteOperationalStoreRepository` constructed over that connection — as the only access to durable kernel records. Every call returns a distinct single-use unit and remembers its connection and correlation identity in a process-local registry of open units; a nested unit on the same thread, an unknown purpose and an unavailable or unmigrated store fail before any record access. The immediate transaction serializes writers, so a record loaded through the unit cannot change before its commit; that is what lets the owning function compare a caller's expected value with the loaded record. Begin publishes no durable change and accepts no SQL, table name, path, credential or untyped payload.
commit_unit_of_work: [BEHAVIOR] MUST commit exactly once the open transaction of the given unit, close its connection, remove it from the registry of open units and return one `UnitOfWorkCommitResult` whose `transaction_id` is the correlation identity the unit was begun with. Key, uniqueness and absent-record violations surface at the record operation that caused them, never at commit; append-only kinds are immutable because the port offers no update or delete for them. A unit that is unknown, already committed or already rolled back, a driver failure and an uncertain commit are explicit and never reported as success or partial publication; after any failure the transaction is rolled back and the connection closed. It commits only kernel records and never business-service or external-file state.
rollback_unit_of_work: [BEHAVIOR] MUST roll back the open transaction of the given unit, close its connection and remove it from the registry of open units, leaving every previously committed record untouched. Repeating the same completed rollback is idempotent and reports `already_rolled_back`, while an unknown unit, a unit already committed, a rollback failure or an unavailable store is explicit; rollback can never delete or reverse durable evidence. No change made through the unit may remain visible, and an uncertain rollback prevents the kernel from serving until startup recovery establishes the transaction outcome.

An exact capture query succeeds only when the referenced immutable NodeExecution matches that slot and contract, and health derivation receives only evidence for the named serving implementation. ## Trial Corpus
active_corpus: [BEHAVIOR] MUST return a stable ordered snapshot of every active TrialCase for the exact contract version plus the content identity of that complete set; internal admission and health callers cannot filter or omit cases. Withdrawn cases never count as active but remain available as historical admission evidence. A surface reader receives full values only within its disclosure ceiling and otherwise receives digest-and-class views; unreadable evidence is an explicit failure and MUST NOT produce a partial snapshot labelled complete.
add_trial_case: [BEHAVIOR] MUST resolve the exact contract version, require one value for every required input and no extras, and validate each draft's term revision, schema, media type and bounds against its corresponding port. It derives the draft carriage from the declared `canonical_bytes` and `byte_stream` fields, requires exactly the representation selected by the port's carriage, stores values and file fixtures with `trial_corpus` retention, derives the case identity from immutable content and appends one active TrialCase; identical content returns the existing case. Unknown or retired contracts, incompatible ports and failed storage leave no partial values or case, and the operation executes no implementation and changes no admission or activation. The contract version MUST be resolved only with `module:slot_registry.contract_version`. `added_at` MUST be one sample of `module:system_clock.now`; no caller supplies or alters it. A file input MUST be judged against the port's `accepted_media_types` and `size_ceiling_bytes`, and a value against `config.release_ceilings.stored_value_bytes_max`; a contract version carries no status of its own.
capture_trial_case: [BEHAVIOR] MUST accept only a concluded function NodeExecution of the exact slot and contract, copy only the selected execution inputs whose values and digests match trace evidence, and record origin `captured_from_run`. A live spool file is verified and copied into a retained `byte_stream` StoredValue while the run keeps ownership of the original; inaccessible or released bytes cannot be captured by reference. Failed execution supplies no inferred expected output, and retaining a file in `rules.disclosure.classes[2]` requires the active owner. The append changes neither serving activation nor a stored health flag. `added_at` MUST be one sample of `module:system_clock.now`; no caller supplies or alters it.
copy_cases_to_version: [BEHAVIOR] MUST operate only between exact versions of the same slot after verifying that the target corpus is empty. Each selected active source case is independently revalidated against target ports, term revisions, schemas, carriage and bounds; compatible cases receive new target-version identities while equal StoredValue content may be reused by digest, and incompatible cases appear as explicit skips with reasons. It MUST NOT copy withdrawn cases, coerce content, infer inheritance at contract creation or alter source cases, admission history or activations. Both contract versions MUST be resolved only with `module:slot_registry.contract_version`.
withdraw_trial_case: [BEHAVIOR] MUST compare-and-set one active TrialCase to final withdrawn state, sampling `module:system_clock.now` once and recording the actor and bounded reason without editing or deleting case content. When a case has expected outputs and ever contributed to an admitted verdict, only the active owner may withdraw it; an authoring agent cannot remove a protected regression that blocks its implementation. Exact replay preserves the original withdrawal, conflicting or stale repeats change nothing, and all prior verdicts, executions, activations and retained references remain historical evidence. The bounded reason MUST be stored as `withdrawal_reason`.

## Value Store
derive_output_class: [BEHAVIOR] MUST derive a function output's disclosure class as the maximum class of the exact StoredValues actually supplied to that execution and return the contributing class evidence. Caller labels and a requested lower class are ignored; missing references, inconsistent execution evidence, unknown classes or a non-function output context fail closed without a fallback. The calculation reads no unrelated run values, does not reclassify operation-service outputs and has no state impact.
expire_values: [BEHAVIOR] MUST sample `module:system_clock.now`, evaluate every live retention reference and terminal-run state, and atomically remove only eligible `run_evidence` bytes after 30 days for personal data or 90 days for other classes. Any non-terminal Run or longer retention reference protects the content; trial-corpus and approval evidence do not expire under this policy. Repeated sweeps are idempotent, and indeterminate run state, inconsistent references or unavailable store abort the affected unit rather than guessing. Digest, semantic/schema/carriage/class metadata, retention history and all records naming the value remain immutable after bytes are removed. The closed flow plan requires this coordinator path to reach the exact operations `now`, `release_run_files`, `rollback_unit_of_work`.
put_value: [BEHAVIOR] MUST consume canonical bounded bytes, validate the accepted semantic-term revision, schema and carriage, compute identity from content and store the object once under its digest with immutable metadata. Equal content reuses the object and may append a longer-lived retention reference; different bytes or metadata can never overwrite an existing digest. Durable `byte_stream` content is accepted only for a trial fixture and must satisfy both stored-value and fixture ceilings. Oversize, invalid references, unreadable streams, non-trial files or storage failure expose no partial StoredValue, and the operation writes no external-service business record.
read_value: [BEHAVIOR] MUST resolve the exact digest within the reader's declared run, trial or inspection purpose and apply the disclosure ceiling before releasing content. When the value is above the ceiling or its bytes have expired, it returns only permitted digest, term, schema, carriage and class metadata with an explicit unavailable reason; it never reconstructs or fabricates content. Malformed references, wrong scope, integrity mismatch and unavailable storage are explicit without alternate-path existence leaks, and the read changes no retention or domain state.
