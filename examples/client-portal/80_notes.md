# transport_guard

install_transport_guards: [ORCHESTRATION] MUST register exactly one FastAPI http middleware on the supplied application. For every request the middleware MUST evaluate the checks below in the order they are written, and the order is a pipeline rather than a choice between alternatives: each check either produces the response named for it and ends the request there, or leaves the request untouched for the next check to evaluate. A check that does not produce a response MUST NOT call the next handler, MUST NOT return, and MUST NOT cause any later check to be skipped; the next handler is called exactly once, after every check in the list has left the request unrefused. The status of each response a check produces is the status_code of the row of the imported TRANSPORT_GUARD_STATUSES constant selected by the = models.TransportGuardRefusal member named in parentheses. The checks are: derive a request id carrying no identity or credential material; reject the request (UNTRUSTED_HOST) when _host_allowed refuses the request host against the trusted_hosts field of the settings; answer an OPTIONS request carrying an Origin listed in the allowed_origins field of the settings with a preflight (ALLOWED_PREFLIGHT) echoing the requested method and headers plus Vary Origin, together with the allow-origin and allow-credentials headers every allowed-origin response carries, and reject an unlisted origin (UNLISTED_PREFLIGHT_ORIGIN); reject POST on the canonical viewer logout path, the imported VIEWER_LOGOUT_PATH constant, (LOGOUT_ORIGIN_MISMATCH) unless _normalized_origin of the request Origin equals _normalized_origin of the public_origin field of the settings; reject (OVERSIZED_BODY) when _body_within_limit refuses the declared Content-Length against the max_request_body_bytes field of the settings; reject (RATE_LIMITED) when _record_viewer_entry_attempt refuses a POST on the canonical viewer entry path, the imported VIEWER_ENTRY_PATH constant, keyed by _client_bucket_key, before any credential parsing or verification. A POST to the viewer logout path whose Origin is accepted therefore still passes through the body-size check, and so does every other request that is not refused before it. It MUST supply _record_viewer_entry_attempt with one reading of monotonic_seconds per entry attempt, a clock that cannot move backwards, never with wall-clock time and never with a host clock read directly, so that adjusting the system clock cannot widen the window or discard recorded attempts. Every response it produces or forwards, including each rejection above, MUST pass through _apply_security_headers with the request id and the _requires_no_store decision for the canonical path, and MUST carry the CORS allow-origin, allow-credentials and Vary headers only when the request Origin is listed in the allowed_origins field of the settings. When the production_logging field of the settings is true it MUST emit exactly one INFO record per completed request, built only by _transport_log_record. It MUST classify every path through _canonical_path so a deployment-prefixed path is treated exactly like its stripped inner path, keep its rate-limit state bounded inside the installed guard, and MUST NOT authenticate a principal, read persistence, import a domain or application module, or import starlette directly.
_canonical_path: [BEHAVIOR] MUST map a deployment path to the inner route path by removing exactly one leading segment equal to the imported API_PREFIX constant, returning / for the bare prefix and the unchanged path when the prefix is absent. It MUST NOT strip the segment more than once, strip a longer prefix, alter query or fragment, or treat a path that merely begins with the letters of the prefix as prefixed.
_normalized_origin: [VALIDATION_ERROR] MUST return the canonical origin: the lowercased scheme, the lowercased host, and the effective port, taking the explicit port when the value carries one and otherwise 443 for https and 80 for http. It MUST return None for a value whose scheme is neither http nor https, and for a value carrying userinfo, a query, a fragment, a non-empty path other than a single trailing slash, or a missing scheme or host. The returned canonical origin MUST discriminate: two values differing in scheme or in host after that lowercasing, differing by any additional host prefix, differing by any additional host suffix, or differing in effective port MUST each receive a different canonical origin. A None result MUST NOT be treated as equal to any value, including another None result.
_host_allowed: [VALIDATION_ERROR] MUST accept the request host only when its lowercased form equals an entry of the supplied trusted host list, MUST reject when the list is empty, and MUST NOT accept a wildcard entry, a suffix match, or a host derived from the public origin or from an allowed CORS origin.
_requires_no_store: [BEHAVIOR] MUST return true for exactly the canonical paths of the imported NO_STORE_PATHS constant, compared as whole paths and never as an abbreviation or a prefix of them. It MUST return false for every other path. The decision depends only on the path: not on the response status, not on whether the response carries Set-Cookie, and not on whether the request succeeded.
_body_within_limit: [VALIDATION_ERROR] MUST accept an absent Content-Length, accept a declared length less than or equal to the limit, and reject a length above it or a value that is not a non-negative integer. It MUST decide before any expensive work and MUST NOT read the request body to measure it.
_client_bucket_key: [BEHAVIOR] MUST build the rate-limit key from the canonical path and the client network identity exactly.
_record_viewer_entry_attempt: [BEHAVIOR] MUST drop attempts older than the window from the bucket for the supplied key, return false without recording when the remaining count is at or above the allowed attempts, and otherwise record the attempt and return true. The supplied now and every timestamp it stores are readings of one monotonic clock that cannot move backwards, so the window is a duration measured on that scale and never a wall-clock interval. Each bucket holds at most the allowed attempts, because a refused attempt is not recorded, and it MUST keep total memory bounded by pruning buckets that hold no attempt inside the window, and MUST NOT distinguish its refusal by account state, by whether a capability exists, or by any other fact about the presented credential.
_apply_security_headers: [SECURITY_BOUNDARY] MUST return the same response with X-Request-Id set to the request id and every header of the imported SECURITY_HEADERS constant set to its value, plus Cache-Control set to the imported NO_STORE_CACHE_CONTROL constant when the no-store decision is true, on rejections and successes alike, while preserving route-owned binary response headers.
_transport_log_record: [SECURITY_BOUNDARY] MUST return the four values under the labels of the imported TRANSPORT_LOG_LABELS constant, in its order: the request id, the method, the canonical_path argument and the status, each written as its label, an equals sign and the value, and joined by single spaces.
