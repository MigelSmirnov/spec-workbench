## The owner's decisions of 2026-11-17, now in the texts

1. **`PERSONAL_DATA_FIELDS`** is a data-provider table of (answer model,
   field) pairs, with row model `PersonalDataField`.
   - An answer is `personal_data` when one of the listed fields holds a
     value. Otherwise it is `business_confidential`; `open` is never
     answered.
   - The table classifies answers only. The uploaded file is never an
     answer's field.
   - A billing answer without a tax id or legal name, and an anonymised
     project's erased form, are `business_confidential`.
2. **`store.opened_store()`** gives the store `open_store` opened.
   `run_in_transaction` and `read_in_transaction` take that store.
3. **`configuration.give_backup_location()`** gives the backup location to
   `operations`. `NewestBackup`'s three outcomes are each rendered as
   themselves.
4. **The service API's wire format is v1's.**
   - The agent-session header is `SERVICE_AGENT_SESSION_HEADER`
     (`Registry-Agent-Session`).
   - Statuses: `SERVICE_ANSWER_STATUS` 200; `REFUSAL_HTTP_STATUSES` gives
     `not_found` 404, `internal_error` 500 and every other code 422.
   - No `answer_kind` or `view_kind` on the wire; `validate` and `context`
     keep v1's fields (R0-04).
   - Instants are ISO 8601 UTC with `Z`; decimals are strings.
5. **CSRF in forms.** `owner_sessions.give_session_csrf` gives the CSRF value
   to `_render_owner_page`. The sign-in form carries none.
6. **The upload sends CSRF first.** A new module, `upload_framing`, owns the
   multipart framing (owner's choice of a module):
   - `read_upload_head` reads the head, at most
     `UPLOAD_FORM_HEAD_MAX_BYTES` (8192). It answers `UploadHead` with the
     CSRF value, the delimiter and the file part's declared length.
   - `MultipartFileBody` is a `policy` implementation of `UploadBody` over
     the new `external` port `ByteStream`.
   - A19 rule 4 now counts the file part: limit, counting and declared
     length (State 2 change; A21 re-reviewed, no outcome changed).
7. **The session cookie is always `Secure`.** The owner chose this over
   "by listen address" after round-54 found a loopback proxy hole.
8. **An upload arrives once its bounded head has been read** (A13 rule 2,
   owner's choice A over a two-phase admission). Both designs were tested
   in `experiments/registry/upload_framing_proto`. The session check
   reads the clock in one hold of the new session-table lock. That lock is
   innermost and short, in the order import, sign-in, session, table, and
   it guards each session's entry, signed-out mark and last-request
   reading.
9. **Listeners.** HTTP framing of both surfaces is `instance_lifecycle`'s.
   - The body stream ends where HTTP's framing ends it.
   - `LISTENER_READ_TIMEOUT_SECONDS` = 30 is a technical value the author
     chose. It is a per-read progress wait, the socket's own timeout.
   - A request answered before its body was read to the end has its
     connection closed.

## Prototypes of the evening (findings not yet in the texts)

The owner asked to prototype the risky parts before the notes. Two
prototypes, under `experiments/registry/`, run with
`python -I -m pytest -q -p no:cacheprovider experiments/registry/<dir>`:

- **`listener_proto`** (20 tests): `instance_lifecycle`'s listener as State 3
  and `60_contracts.md` "The listeners" state it — `Content-Length` and
  chunked framing, refusal of malformed framing headers from the headers
  alone, the per-read socket timeout, the close after an unread remainder.
  The framing, the timeout and the no-smuggling close behave as written.
  **Finding:** "the remainder discarded unread and its connection closed",
  done as a plain `close()`, loses the answer. With bytes still unread,
  the kernel sends RST and drops whatever it had not yet sent. On loopback
  an answer above about 100 KB never reached a client still sending its
  body (0 of 4), and over a WAN much smaller answers would be cut. A staged
  close per RFC 9112 §9.6 delivered every answer (4 of 4): `shutdown(SHUT_WR)`,
  then read and drop what the client still sends for a bounded time and
  size, then `close()`.
  - **Text to change:** State 6 "The listeners" and State 3
    `instance_lifecycle`. Their round follows the change.
  - **Values to choose:** the bound of the staged close (time and bytes).
    The prototype used 2 s and 64 MiB.
  - **Caveat:** an early answer larger than the socket buffers, sent to a
    client that reads only after it has sent everything, blocks both sides
    until the timeout. A 3 MB answer failed in both modes. Early answers are
    refusal pages and stay small.
- **`session_locks_proto`** (9 tests): `owner_sessions`' four locks
  (Conventions "Locks of an owner request", `admit_owner_request`,
  `sign_out_owner`, `end_expired_sessions`), with forced interleavings and a
  12-thread stress test.
  **Finding:** where a request asks for its turn decides whether the
  admission order holds. The text releases the table lock "before it waits
  for the import lock or a place on the session's lock". Read literally,
  the request asks for its turn after that release, and a request admitted
  later can take its turn first. Three cases show it:
  - a sign-out admitted after a change takes the session's lock first, and
    the change then runs in an ended session, against `sign_out_owner`'s
    "each completes first";
  - the 60-second pass does the same to a change admitted before it began;
  - a second upload gets the import lock before the first.

  Drawing the turn inside the arrival's hold fixes all three, and the
  stress test finds no deadlock. The turn is a ticket of the import lock or
  a place on the session's lock, drawn without waiting, and the wait comes
  after the release. "A request asks for the import lock when it is
  admitted" already points that way; a change's place "at once" does not
  say it.
  - **Text to change:** State 5 Conventions and `admit_owner_request`
    should say the turn is drawn in that hold, and that drawing it waits for
    nothing, so "no holder of the table lock waits for another" still holds.
    The State 5 round follows.
- **The question carried to State 7** (a body that cannot be read): the
  prototype shows that a client which stalled is still waiting, and gets the
  answer when the request is handed on without values. When the client
  reset the connection, there is no one to answer either way.
