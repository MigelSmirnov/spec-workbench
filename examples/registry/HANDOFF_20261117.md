## Waiting on the owner: the surfaces (structure requests of `service_api` and `owner_interface`)

1. The `Registry-Agent-Session` header name has no home. It needs a
   data-provider constant.
2. The HTTP status of each answer and of each `RefusalCode` is fixed by no
   text. v1 used 404/422/500 (`SOURCE.md`). This is the owner's decision.
3. The JSON form of non-refusal answers is open:
   - whether `answer_kind`/`view_kind` go on the wire;
   - whether `validate`/`context` keep v1's fields (R0-04);
   - how instants and decimals are encoded.
4. After sign-in, the CSRF value has no path into later forms:
   `_render_owner_page` gets none, and no `owner_sessions` operation gives
   it for an admitted session.
5. **The upload conflicts with CSRF (owner).** An upload is a change, so it
   needs CSRF (A13 rules 2 and 5), and the value travels only in forms
   (rule 7). A script-free form sends the file as multipart, so the CSRF
   field sits inside the body that must reach `_read_bounded` unread, and
   `_parse_export` expects a bare JSON object.
6. The rule "HTTPS-only cookie when reached from another machine" has no
   input: `HttpRequest` has neither peer nor scheme, and `owner_interface`
   receives no configuration.

## Choices delegated authors made (worth a look)

- **`load_configuration`:** a diagnostic names the item by its
  `RuntimeSettings` field name.
- **`customers`:**
  - eligibility is checked in the order erased, restricted, ended;
  - an erasure leaves only `customer_ref` and `erased_at`, so
    `last_changed_at` is None too.
- **`projects`:** a create's repeat compares facts as text (`"45"` ≠
  `"45.00"`), and an imported project's object holds only the v1 address.
- **`backups`:**
  - the kept name's exact form is the generator's, a fixed-width UTC
    instant after `BACKUP_KEPT_PREFIX`;
  - HKDF has no salt;
  - the associated data is the record line without its line feed.
- **`migration_import`:**
  - positions count from zero;
  - the import closure's principal is the owner;
  - a pick refused at stage 4 is `mapping_not_clean` at confirmation.
- **`instance_lifecycle`:**
  - the listener, not `owner_interface`, closes a connection whose body was
    not read;
  - the service API's `body: bytes` has no size bound, which is a gap to
    confirm.
