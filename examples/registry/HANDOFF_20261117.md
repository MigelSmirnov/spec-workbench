## Surfaces: decided by the owner on 2026-11-17, not yet applied

The structure requests of `service_api` and `owner_interface`. Each item
gives the question and then the owner's answer.

1. The `Registry-Agent-Session` header name has no home. **Decided:** a
   data-provider constant holding exactly `Registry-Agent-Session` (for
   example `SERVICE_AGENT_SESSION_HEADER`), imported by `service_api`.
2. The HTTP status of each answer and of each `RefusalCode` is fixed by no
   text. **Decided: as in v1** (`SOURCE.md`):
   - an accepted answer is 200;
   - a refusal that names a missing record is 404;
   - every other refusal is 422;
   - `internal_error` is 500.

   The mapping is a data-provider table from `RefusalCode` to status, so
   that no status is written as prose.
3. The JSON form of non-refusal answers. **Decided: v1-compatible.**
   - `answer_kind`/`view_kind` do not go on the wire.
   - `validate`/`context` keep v1's fields (R0-04).
   - Instants are ISO-8601 UTC with `Z`.
   - Decimals are JSON strings, in the stored form (`"45.00"`).
4. After sign-in, the CSRF value has no path into later forms:
   `_render_owner_page` gets none, and no `owner_sessions` operation gives
   it for an admitted session. **Decided:** an `owner_sessions` operation
   gives the admitted session's CSRF value, for example within the
   admission's answer. `owner_interface` passes it to `_render_owner_page`.
   The value stays held by `owner_sessions` only.
5. **The upload conflicts with CSRF.** An upload is a change, so it needs
   CSRF (A13 rules 2 and 5), and the value travels only in forms (rule 7).
   A script-free form sends the file as multipart, so the CSRF field sits
   inside the body that must reach `_read_bounded` unread, and
   `_parse_export` expects a bare JSON object. **Decided: CSRF is the first
   multipart part.**
   - The upload form puts the CSRF field first.
   - `owner_interface` reads only that part, bounded, and checks it.
   - The file part's content goes on as the bounded, unread stream, so
     `_parse_export` still receives a bare JSON object.
   - A body whose first part is not the CSRF field is refused before any of
     the file is read.
   - A13's rules stay as they are. The contract "the body reaches
     `_read_bounded` unread" becomes "the file part reaches it unread" in
     States 5 and 6.
6. The rule "HTTPS-only cookie when reached from another machine" has no
   input: `HttpRequest` has neither peer nor scheme, and `owner_interface`
   receives no configuration. **Decided: by the listen address.**
   - The cookie is `Secure` when Registry listens on an address other than
     loopback.
   - The listen address is already configuration. It only needs a path to
     `owner_interface`.
   - A TLS proxy on the same machine is the host's concern (Explicit
     exclusions).
