## Исправления

### `registry_a05_every_repeated_transition_answers_unchanged` — исправлен
- Было: повторная регистрация проверялась сразу после первой, когда у сессии пустой набор, нет активного проекта и версия 1. Мутант «регистрация всегда создаёт сессию заново» (A11 rule 4 применён к живой сессии) давал тот же ответ и проходил, если сохранял `registered_at`.
- Стало: до повторной регистрации сессии выдан проект и он сделан активным; повтор обязан вернуть именно этот доступ (`again["access"] == granted["access"]`), `registered_at` прежний.
- Основание: A05 rule 1 («registering a registered session»), State 5 `register_session` («A registered session is answered unchanged»), M06 («registering it again returns it unchanged»).

## Ожидаемые значения
- `changed: false` у повтора, `changed: true` у изменения: State 5 Conventions «Repeats»; поле `changed` у `CustomerAnswer`, `ProjectCardAnswer`, `ProjectErasedAnswer`, `SessionAccessAnswer` (State 6).
- Ревизия 1 у новой записи и +1 за изменение: `REVISION_FIRST = 1`, A04-3; версия доступа 1 у новой сессии и +1 за изменение: `ACCESS_VERSION_FIRST = 1`, State 5 `grant_project`, `set_active_project`.
- Записи аудита `customer_restricted`, `project_archived`, `project_anonymised`, `customer_erased`, `session_project_granted`: `OWNER_AUDIT_ACTIONS`. `confirmation_id` у архивирования: A14 rule 5, ConfirmedAction `archive_project`.
- Повтор стирания стирает без ревизии (`stated_version=None`): A04 rule 3, State 5 `erase_customer_contact`, `erase_project`.
- `refused`, стадия 6, виды `withdrawn`, `superseded`, `archived`: State 5 «Closed set of refusal codes»; `withdraw_pointer`, `grant_project` Errors; `REFUSAL_STAGE_LIFECYCLE = 6`.
- Дата завершения не позже сегодняшней (2026-01-05): State 5 `mark_customer` (4) `date_after_today`.

## Оставшиеся ограничения
- «Подтверждающий id не создаётся» наблюдается только как отсутствие записи аудита: id нигде больше не виден (A14 rule 5 — он пишется только в запись). Мутант, который создаёт id и никуда его не пишет, ненаблюдаем и не нарушает ничего наблюдаемого.
- `store_rows` сравнивается по всем восьми таблицам `70_persistence_closure.json`; допущение — имена таблиц, которые принимает `store_rows`, это имена `table` закрытия (`project_rows`, …).
