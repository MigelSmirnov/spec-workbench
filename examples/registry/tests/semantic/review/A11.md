## Исправления

### `registry_a11_reregistered_ended_identity_empty` — исправлен
- Было: только «регистрация после завершения даёт пустую сессию». Мутант M2 «регистрация всегда создаёт пустую запись» проходил.
- Стало: перед завершением живая сессия регистрируется повторно и возвращается без изменений (`changed: false`); после — `changed: true`.
- Основание: A11 rule 1 («registering a registered session answers it unchanged (A05)»), A11 rule 4, `register_session` Observable effect.

### `registry_a11_ended_session_leaves_no_record` — исправлен
- Было: проверка строк только после завершения Kernel. Мутанты M2 и M4 проходили.
- Стало: завершены две сессии разными принципалами; журнал аудита сравнивается до и после.
- Основание: A11 rules 2, 3, 6; State 5 `end_session` Enforces «no entry (A11 rule 6)».

### Сторонняя проверка Codex judge-checks (2026-11-24)
- `registry_a11_ended_session_access_read_refused` и `registry_a11_owner_ended_session_call_refused` (судья: `partial`, «не осталось записи» не проверено): до завершения — контроль, что у сессии одна строка `agent_session_rows`; после — ни одной строки, называющей её. Во втором тесте у другой сессии строка остаётся.
- `registry_a11_ended_session_leaves_no_record` (судья: `partial`, «не зарегистрирована» не проверено): после двух завершений вызов Kernel с каждой завершённой сессией получает ответ A10 rule 3, поле в поле как для никогда не регистрированной. Владелец получает `not_found`/3/`unknown_session` и не видит их в списке. Контроль: живая сессия отвечает и есть в списке. Чтения не меняют таблицу сессий.
- `registry_a11_reregistered_ended_identity_empty` не менялся: судья подтвердил A11-2 и упрекнул только в A11-1, которого пункт не называет (SUMMARY.md, класс 2).
- Основание: A11-1 (`not registered(x) and no record of x remains`), A11 rules 3, 4; State 5 `check_agent_call`, `read_session_access` Errors.

## Ожидаемые значения
- `not_found`/(2)/`agent_call_refused` для Kernel и `not_found`/(3)/`unknown_session` для владельца: State 5 closed set, `agent_sessions.read_session_access` Errors.
- Новая сессия после завершения: `ACCESS_VERSION_FIRST = 1`, пустой набор: A11 rule 4, `register_session`.
- Записи аудита о сессии — гранты (`session_project_granted`, `SessionProjectSubject`): `OWNER_AUDIT_ACTIONS`, M09.
- Таблица `agent_session_rows`: `70_persistence_closure.json`, `config.persistence.agent_session_table_name`.

## Оставшиеся формальные / ограничения
- `store_rows` отдаёт строки в форме фикстуры; тест ищет идентификатор сессии в сериализованной строке целиком (`json.dumps(row, default=str)`), поэтому не зависит от того, отдана ли колонка `record` текстом или словарём.
