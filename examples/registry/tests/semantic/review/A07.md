## Исправления

### `registry_a07_failed_publish_leaves_nothing` — исправлен
- Было (первый набросок): один сбой «на транзакции». Мутант L07 (две отдельные транзакции) при сбое первой транзакции тоже ничего не оставлял и проходил.
- Стало: сбой на конкретном методе репозитория, по очереди на обеих записях публикации; плюс повтор той же публикации тем же request id после сбоев — версия 2, `changed: true`.
- Основание: A07 rule 1 («all in one transaction, or none of it»), A07-2, A07-4; State 6 «Failures» (сбой поднимается в `store`, откат, `internal_error`/`transaction_failed`).

### Выравнивание по итоговой RUNTIME_SURFACE.md (2026-11-24)
- `rt.fail_store_call(method)` → `rt.faults.fail_store_call(method)` (методы те же: `insert_pointer_row`, `update_pointer_row`). Docstring: возможность и параллельные вызовы (`Concurrency`) теперь в поверхности. Строки таблицы не меняются.

## Ожидаемые значения
- Версия 1, затем max+1; одна `published` на тип: A07-1…A07-3; State 5 `publish_pointer` Observable effect.
- `internal_error`, стадия `None`, вид `transaction_failed`: State 5 «Closed set of refusal codes» (`internal_error` без стадии), State 6 «Failures».
- `refused`/6/`superseded`, `archived`: State 5 `withdraw_pointer`, `publish_pointer` Errors; `REFUSAL_STAGE_LIFECYCLE = 6`.
- Latest после отзыва — «none is published»: State 5 `latest_pointer_of_type` Outputs.

## Нужные возможности фикстуры (нет в RUNTIME_SURFACE.md)
- `fail_store_call(method: str) -> None` — следующий вызов метода `method` класса `SqliteStoreRepository` (State 6 `StoreRepository.<method>`, `70_persistence_closure.json`; здесь `insert_pointer_row`, `update_pointer_row`) один раз поднимает ошибку драйвера; `store.run_in_transaction` откатывает транзакцию, операция отвечает `internal_error` (`transaction_failed`). Отличие от `fail_next_write_transaction` (A14/A16): сбой при коммите не отличает два коммита L07 от одного.
- Параллельные вызовы `service(...)` из нескольких потоков (тот же запрос, что у A01 test 12): каждый вызов — свой HTTP-запрос к слушателю сервисного API.

## Оставшиеся ограничения
- RT1 и RT4 ловят мутанта гонки, только если две нити действительно пересекаются в Registry. Барьер и 10 раундов делают это вероятным, но не гарантируют; последовательное исполнение A07 rule 2 делает неразличимым. Детерминированно гонку можно было бы вызвать только остановкой внутри транзакции — такой возможности нет и она была бы ниже поверхности.
