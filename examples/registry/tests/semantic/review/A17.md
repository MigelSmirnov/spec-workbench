## Исправления

### `registry_a17_failed_check_stops_before_any_listener` — исправлен
- Было: после неудачного старта проверялось только, что порты не принимают соединения. Мутант «открыть слушатели, проверить хранилище, закрыть» проходил: к моменту возврата `start()` порты закрыты.
- Стало: каждый случай запускается дважды — со свободными портами и с занятым портом владельца; диагностики обязаны совпасть. Хранилище с неверной версией — настоящая SQLite-база с `user_version = 2`; «новое хранилище нельзя сделать» — каталог на месте временного имени (`.new`), который старт не может удалить как файл (rule 5), — не зависит от прав root. Каталог копий — обычный файл, так что срабатывает именно проба, а не проверка «раздельности» путей.
- Основание: A17 rule 2 (порядок проверок, «last, the listener of each surface»), 80_notes.md `start_instance` [ORCHESTRATION].

### `registry_a17_service_address_with_tokens_and_wellformed` — исправлен
- Было: литеральный порт 8781 из Required test. Чужая программа на 8781 сломала бы `_stops` (порт «принимает»), а не Registry.
- Стало: общий порт — свободный порт хоста; суть («один порт у двух адресов») та же. Добавлен `:65536` (верхняя граница `LISTEN_PORT_MAX`).

### `registry_a17_missing_token_stops_start_none_owner_only` — усилен при написании
- Добавлен случай двух пропущенных токенов: мутант, называющий любой пропущенный, кроме первого по порядку rule 1, проходил бы.

### `test_new_store_holds_only_audit_sequence_at_zero` — исправлен
- Было: версия хранилища читалась напрямую `PRAGMA user_version` — вне поверхности.
- Стало: версия показана наблюдаемым следствием rule 5: второй старт над этим хранилищем проходит, а хранилище другой версии старт отвергает (тест 10).

## Оставшиеся формальные / ограничения
- M4 первого теста частично: owner-only Registry, открывший API сервисов на *своём* порте по умолчанию (не на сконфигурированном), ловится только если `service()` фикстуры стучится туда же; поверхность этого не задаёт.
- Ветка «новое хранилище не удалось удалить → остаётся пустое хранилище версии релиза» (rule 2, тест 5) не вызывается: каталог теста доступен для записи, а сделать удаление невозможным, не мешая созданию, через поверхность нельзя.
- «Старт, прерванный до переименования, не оставляет хранилища под его именем» (тест 6) показан только как его последствие: файл временного имени, оставленный прерванным стартом, удаляется следующим. Само прерывание требует новой возможности (`faults.interrupt_start_before_store_rename()`); не запрошена — тест не витнес.
- «Ни одна неизвестная переменная не попадает в настройку» (тест 7): `RuntimeSettings` имеет закрытый набор полей (State 6) — структурно; через поверхность не наблюдаемо.
- Хранилище, открывающееся, но не проходящее `PRAGMA integrity_check`, не построено: используется файл, который не открывается как SQLite. Повреждение страниц индекса в тесте было бы хрупким.
- Тесты 9 (`[::1]`, `[::]`) требуют IPv6 loopback на хосте Factory.
- Предположения о фикстуре: `configure(x=None)` снимает элемент; после неудачного `start()` экземпляр остановлен и `configure`/`start` можно повторить; `store_rows` читает файл и при остановленном экземпляре.
