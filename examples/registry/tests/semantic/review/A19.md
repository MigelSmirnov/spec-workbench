## Исправления

### `registry_a19_access_request_markup_shown_as_text` — исправлен
- Было: текст с `<b>…</b>`, и проверка «тега `b` нет на странице». Страница со своим `<b>` давала ложный провал, а ослабленная проверка («`b` есть, но текст целиком») пропускала мутанта, у которого из значения получился элемент `b`, если в тексте случайно осталась та же строка.
- Стало: в тексте выдуманный тег `zb` и `img` с `onerror`; ни одного из них нет среди элементов, атрибутов `onerror`/`src` нет, текст виден целиком.
- Основание: A19 rule 1, Required test 2; `_render_owner_page` [TEST_EVIDENCE] «the page holding no element and no attribute made from it».

### `registry_a19_query_language_in_name_not_executed` и `registry_a19_import_values_read_as_text_not_evaluated` — исправлены
- Было: на свежем хранилище `DROP TABLE`/`DELETE` нечего было удалять — мутант M1 не отличался по `store_rows`.
- Стало: до опасной записи создаются проект с комнатой (и клиент для импорта); проверяется, что каждая прежняя строка осталась.
- Основание: Required test 6 («the store afterwards holds what it held before, unchanged»).

### `registry_a19_every_shown_value_escaped_csp_forbids_script` — усилен
- Значение ссылки — идентичность агентской сессии (записывается как дана, R0-53) с `?#/=+% `; проверяется каждая ссылка и форма с `target` на страницах списка и сессии: ровно один параметр `target`, равный значению целиком, путь из `OWNER_ACTIONS`, без фрагмента.
- Место «значение атрибута» — шаг подтверждения импорта, который по State 7 обязан нести выбор как поля формы.

### Выравнивание по итоговой RUNTIME_SURFACE.md (2026-11-24)
- `_csrf`: было «словарь или объект»; стало `rt.owner_session().csrf` — поверхность возвращает объект с `.cookie`/`.csrf`. Строки таблицы не меняются.

## Оставшиеся формальные / ограничения
- «Каждое хранимое значение» Required test 5 показано на представительном наборе (имя, псевдоним, адрес проекта, имя комнаты, имя клиента, текст запроса, идентичность сессии, имя и псевдоним выбора импорта) и страницах (`/`, `/read_project`, `/list_customers`, `/read_customer`, `/list_sessions`, `/read_session`, `/show_import_mapping`, `/show_confirmation`, отказ, вход). Указатели (`uri`, `payload_ref`), телефон/почта/юр. имя клиента и журнал аудита на страницах не проверены: формы этих значений (A02/A22) могут отвергнуть такую строку, а угадывать их не стал. Остальное покрывает утверждение решения «every page is made by one renderer».
- Какие значения страница пишет в атрибуты, кроме шага подтверждения, дизайн не фиксирует; проверено одно гарантированное место.
- Происхождение ссылок (`scheme`/`netloc`) проверено только как отсутствующее или `http(s)` — адрес слушателя поверхность не даёт.
- Required test 4: «также когда объявленная длина меньше» проверено для длины меньше на один байт. Если объявленная длина обрезает сам файл, State 5 (`serve_owner_request`: «A file whose bytes run past that end lacks its closing delimiter and is refused as `file_unreadable`») даёт `file_unreadable`, а не `file_too_large` — см. находку в отчёте.
- Требуются вызовы `owner_session()` с полем `csrf` и `owner_http(..., form=...)` для POST шага подтверждения; форма `export_file` (поля записей без `position`) — предположение, его должна подтвердить фикстура.
