## Исправления

### `registry_a03_customer_correction_replaces_editable_facts` — исправлен
- Было: равное исправление проверялось без контроля. Мутант, сравнивающий для «равенства» лишь имя (или лишь обязательные поля), проходил: первое исправление меняет имя, а равное — ничего.
- Стало: добавлено исправление, отличающееся от сохранённого только необязательным email; ожидается `changed: true`, ревизия +1, `last_changed_at` = текущий момент.
- Основание: A03 rule 4 («gives exactly the stored facts»), A03-3; A04-3.

### `registry_a03_correction_without_alias_clears_it` — усилен при написании
- Контрольное исправление с алиасом добавлено до очищающего, чтобы мутант «алиас нередактируем» не проходил как «очищено при создании»; вместе с алиасом не даются вид и этаж объекта, а площадь и число комнат даются — так видно, что очищается именно не данное.

### Выравнивание по итоговой RUNTIME_SURFACE.md (2026-11-24)
- После каждого `clock.advance(hours=1|2)` добавлен `rt.sign_in()` (5 мест): `owner()` больше не входит сам, если сессия уже открывалась, а час без запроса — за 30 минутами простоя (A13 rule 2). Без этого правильный Registry отказал бы `no_owner_session`. Строки таблицы не меняются.

## Ожидаемые значения
- `refused` / стадия 6 / `customer_restricted`: State 5 `correct_project` Errors и «Closed set of refusal codes»; `REFUSAL_STAGE_LIFECYCLE` = 6.
- `changed: false` для равного исправления: State 5 Conventions «Repeats», A03 rule 4.
- Ревизия начинается с `REVISION_FIRST` = 1, каждое принятое изменение +1, `last_changed_at` = момент действия: State 1 «Revisions and times», A04-3.
- Площадь сравнивается как `Decimal`, а не текст: State 6 `Object.floor_area_m2: Decimal`, точная текстовая форма хранения тестом не утверждается.
- Сохранение request id наблюдается только через повтор создания (A01 rules 4, 8, 9): request id никогда не отвечается.

## Оставшиеся формальные / ограничения
- A03-2 для проекта (сохранение request id проекта) показан не здесь, а только для клиента — Required tests A03 требуют его лишь в тесте 4.
- Проверка «ни одной записи аудита» опирается на `read_audit` (owner) по действию `project_corrected`; форма записи на проводе (`action` как строка значения) — по RUNTIME_SURFACE «an enum as its value string».
- Отказ проверяется по коду, стадии и видам; `path` не проверяется — для `customer_restricted` State 5 не называет путь однозначно.
