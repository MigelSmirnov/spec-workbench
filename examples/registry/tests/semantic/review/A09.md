## Исправления

### `registry_a09_answer_above_class_refused_whole` — исправлен
- Было (первый набросок): только отказ `context` для PresuPro с пониженным классом. Мутант M1/M4 (класс по операции или по наличию поля в модели) проходил: `context` личный при любом определении.
- Стало: добавлены `billing` компании с `tax_id` (отказ целиком, вид клиента тоже не раскрыт) и `billing` персоны без фискальных данных (ответ), плюс `validate_project_reference` (ответ) и тот же `context` для Portal (ответ целиком).
- Основание: State 5 `perform_service_operation` Enforces — «`personal_data` when one of the fields the imported `PERSONAL_DATA_FIELDS` constant lists holds a value in it, nested views included»; 30_modules.md `operations`; R0-83 (не записанное значение — отсутствует, не отказ).

### `registry_a09_context_portal_answered_kernel_refused` — исправлен
- Было: вызов Kernel без сессии. Мутант «стадия 2 раньше стадии 1» отказывал бы `agent_call_refused` — тест бы это поймал, но не отличил бы «права» от «сессии» при мутанте, который отказывает `not_permitted` за отсутствие сессии.
- Стало: сессия зарегистрирована и держит проект; контроль `read_agent_projection` по той же сессии отвечен.
- Основание: A04 rule 6 (порядок стадий), A09 rule 3, A10 rule 1.

### Выравнивание по итоговой RUNTIME_SURFACE.md (2026-11-24)
- `_view(answer, name)`: было «принимает и вид без обёртки, и `{name: {...}}`»; стало — только голый вид, с утверждением, что под `name` нет вложенного словаря (R0-04, поверхность «`validate` and `context` return the bare view»). Ограничение про обёрнутую форму снято.
- Docstring: `configure_release` в поверхности; пометка «NOT YET» снята. Строки таблицы не меняются.

## Оставшиеся формальные / ограничения
- **A09-2 и половина A09-3 ненаблюдаемы в релизе v1.** Ни один ответ операций Kernel (`SessionAccessAnswer`, `SessionEndedAnswer`, `RequestPendingAnswer`, `ValidationAnswer`, `AgentProjectionAnswer`, `RoomsAnswer`, `RoomAnswer`, `PointersAnswer`, `LatestPointerAnswer`, `PointerAnswer`) не содержит поля из `PERSONAL_DATA_FIELDS`, а у остальных трёх служб высший класс — `personal_data`. Значит `answer_above_class` в v1 не возникает ни при каком запросе. Тесты 5 и 6 написаны на тестовом релизе через запрошенную возможность `configure_release(**constants)` (нет в RUNTIME_SURFACE.md). Без неё мутант «проверки класса нет вовсе» неотличим от правильного Registry.
- Форма `context`/`validate` в ответе фикстуры: по RUNTIME_SURFACE.md («answers are the wire answers») это вид без обёртки (60_contracts.md, R0-04); хелпер `_view` принимает и обёрнутую форму `{"context": {...}}`, утверждения — по полям вида.
- A09 rule 1 «конфигурация держит токены, не права» и rule 5 «ни один токен не несёт прав владельца» отдельными тестами не показаны (их нет в Required tests).
